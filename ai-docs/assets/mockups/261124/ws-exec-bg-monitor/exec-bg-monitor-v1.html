시안별 비교 및 뱃지 역할 분리

시안 팝업 폭 / 공간 점유 다단계 자손 계층 가독성 실시간 로그 테일 편의성 추천 상황
A안 (트리 아코디언) 좁음 (~460px)
대화창 가림 최소		 최상 — 부모→자식→손자 들여쓰기가 한눈에 들어옴 보통 — 1개씩 펼쳐서 확인, 작업이 많으면 스크롤 증가 좁은 분할 화면에서 계층 파악 위주로 가볍게 확인할 때
B안 (2단 마스터-디테일) 넓음 (~680px)
좁은 화면엔 상하 스택		 우수 — 좌측 트리 고정으로 컨텍스트 유지 최상 — 넓은 우측 테일창에서 여러 작업을 빠르게 오가며 관찰 긴 빌드·테스트(45분 go test 등)를 핀 고정해 계속 볼 때
C안 (플랫 + 하단 도킹) 중간 (~500px)
세로 밀도 가장 높음		 양호 — L1/L2 배지 + 브레드크럼으로 깊은 트리도 평탄화 우수 — 목록과 5~6줄 테일을 동시에 보며 키보드(↑↓)로 전환 자손 에이전트가 많고(5개+) 공간 효율·빠른 전환을 모두 원할 때
뱃지 역할 분리 원칙: N 백그라운드 작업 뱃지는 현재 리드(본인)와 모든 자손 에이전트가 ws/exec로 실행해 백그라운드로 전환된 작업을 재귀 합산해 모니터링합니다. 반면 사용자가 입력창 ! 또는 전용 실행 경로로 직접 띄운 명령은 기존 전용 >_ 뱃지(앰버 링 · origin: "user")로 분리 유지해, 에이전트 백그라운드 작업과 사용자가 직접 실행한 명령이 섞이지 않도록 합니다.
