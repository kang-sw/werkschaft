대화창 ! 명령 — 터미널처럼 보이게 (디자인 제안 · 2026-11-23)

현재 구현(261121-feat-ws-board-command-slots): 컴포저 맨 앞 글자가 !이면 서버가 bash 명령으로 실행하고, 결과는 컴포저 안 카드 띠(.d-cexec)에, 등록된 명령은 그 위 슬롯 띠(.d-ucmd)에, 실행 중 작업은 컴포저 틈의 HUD 칩에 보인다. 아래 세 방향은 같은 동작 위에 보이는 것만 바꾼다. 서버의 첫 바이트 문법, 앞 공백이면 일반 메시지라는 규칙, 슬롯이 저장된 줄을 그대로 전부 보여 주는 규칙은 세 방향 모두 유지한다.

각 열: ① 대기 · ② ! 입력 즉시 · ③ 짧은 출력 완료 · ④ 실패(stderr, exit≠0) · ⑤ 긴 출력 → 파일 · ⑥ 비동기 실행 중 · ⑦ 명령 슬롯
지금 데이터 카드 JSON에 이미 있음 클라이언트만 JS/CSS만 바꿈 새 필드 서버가 카드·목록에 덧붙여야 함 (추가 필드, T0) 주의 기존 동작과 맞물림

A셸 틴트

자리와 구조는 지금 그대로 두고 입력칸만 터미널색으로 바꾼다. 맨 앞 !를 지우지 않고 그대로 프롬프트 기호로 쓴다. 결과 카드는 지금 카드에 $와 상태 칩만 더한다.

B콘솔 창

결과 카드 띠를 터미널 창 하나의 스크롤백으로 바꾼다. 창 제목에 셸과 cwd를 보이고, 각 실행은 프롬프트 줄, 출력, 상태 줄 순서다. !를 치면 입력칸이 이 창의 맨 아래 줄로 붙는다.

C프롬프트 캡슐

맨 앞 !가 powerline 모양 모드 캡슐(bash ❯ ~/work/demo)로 바뀌어 입력칸 앞에 붙는다. 슬래시 명령 캡슐 .ccmd와 같은 자리다. 결과는 상태 세그먼트가 붙은 영수증 카드로, 슬롯은 명령 줄이 주인공인 키캡으로 보인다.

추천: A의 입력칸 + B의 결과 기록 + C의 슬롯 키캡을 두 단계로
  1. 1단계, 클라이언트만: A의 입력칸(!는 텍스트에 그대로, 칠하기만), B 방식의 콘솔 창 결과 띠(프롬프트 줄, 출력, 상태 줄; 상태에는 지금 있는 종료 코드, 바이트, job ID만), C의 슬롯 키캡, 팝업 끄기, Esc 규칙. 서버, 라우트, i18n 키 몇 개 말고는 바꾸지 않는다.
  2. 2단계, 추가 필드(T0): 카드에 시작·종료 시각, 스트림 segments, 미리보기 tail, 목록 응답에 cwd와 셸 이름. 들어오면 시간, stderr 색, cwd 제목이 켜진다. 없으면 그 요소만 빠진다.
  3. C의 캡슐 입력은 하지 않는다. 가장 "모드"처럼 보이지만 !를 텍스트 밖으로 빼므로, 네 번의 리뷰를 거친 초안, 확인, 재시도 로직(cexecAcknowledged, cexecPending, cexecAttached)을 다시 건드려야 한다.
