# Fixed Gallery Workpanel Variant B (Todo, Agenda, Notes, Manuals) and Legacy Drawer Workpanel Card Retirement

## Background

### Context

Track 1 (`261128-feat-ws-dashboard-ide-shell-overhaul`) overhauled the outer Variant D shell chrome while deliberately keeping `#drhandle`, `#ghandle`, `#thandle`, and `#bgal` internals unchanged until Track 2. Track 2 splits the session workspace migration into three focused tracks:

- **Track 2A** (`261128-feat-ws-dashboard-always-open-gallery-and-ticketmap`): converts `#bgal` into an always-open pinned gallery, installs the `.gal-rail` system panel slots (`Workpanel`, `Ticket Map`, `Git`), migrates Ticket Map into its dedicated gallery page, and retires `#p-mailbox` and `#p-tickets`.
- **Track 2B** (separate Git/Worktrees ticket): delivers the standalone `Git` gallery page (commit graph, working-tree diff, `Review Ledger`, and `Worktrees`) and retires `#ghandle`.
- **Track 2C (this ticket)**: implements the complete **Workpanel (Graybox B)** system page inside `#bgal` for the 4-item Workpanel scope (`Todo`, `Agenda`, `Notes`, `Manuals`), adds the on-demand `GET /s/<rid>/manuals` endpoint, and retires the Todo, Agenda, and Notes cards of the legacy top-right `#drhandle` / `#drawer` sheet. The sheet itself stays live, hosting only `#p-worktrees` and `#p-holders`, until the tickets that own those surfaces land (see `## Decisions`, Legacy Retirement).

### Goals

1. Implement the **Workpanel (Graybox B)** system page inside `#bgal` matching the approved visual reference `ai-docs/assets/mockups/261128/gallery-workpanel-b/index.html` across Wide (`>= 540px`), Narrow (`< 540px`, e.g., `380px`), and Empty states in both Dark and Light themes.
2. Render live `Todo` and `Agenda` working memory from `#r-panels` (preserving incremental `panel-rows` SSE patching via `dashboard-stream.js`) in a responsive `@container` layout.
3. Implement the lower tabbed Reference Surface (`Notes` | `Manuals`), preserving `GET/POST /s/<rid>/notes` 4-layer filtering and LAN `repo`-only enforcement (`notes.go`), adding `GET /s/<rid>/manuals` wrapping `wsdoc.ManualsList`, and opening clicked manuals in `window.WsPreview.open(path, { keep: true })`.
4. Retire the `Todo` and `Agenda` cards (Phase 1, when `#r-panels` moves) and the `Notes` card (Phase 2) of the legacy top-right `#drawer` workpanel sheet (`#p-notes` drawer card, their `panelTab` registrations) cleanly once all four live sections operate inside `#bgal`, leaving a slimmed `#drhandle` sheet that hosts only `#p-worktrees` and `#p-holders` transitionally.

### Non-Goals

- `#p-mailbox` and `#p-tickets` (retired in Track 2A; Ticket Map is its own gallery system page).
- `Review Ledger` (moved to the Track 2B standalone `Git` gallery page per `(1726)=a`).
- Global Holders (`#p-holders` / `hdLoad`) migration (moves to a separate bottom-bar popup per `(1717)=a`, owned by the follow-up `global-holders-popup`, which has no ticket yet; `#p-holders` stays in the slimmed drawer until then).
- `#ghandle` / `#gbody` and `worktrees` (`#p-worktrees` / `wtLoad`) retirement (untouched until Track 2B `261128-feat-ws-dashboard-gallery-git-page` lands; `#p-worktrees` stays in the slimmed drawer until then).
- Removing `#drhandle` and `#drbody` / `#drcards` entirely (the last of `global-holders-popup` and Track 2B to land removes them).
- Changing `wsdoc.ManualInfo` / `wsdoc.ManualsList` on-disk behavior or `wsnote` storage semantics.

## Decisions

- **Compatibility tier: T0 transparent.** Adds one read-only HTTP route (`GET /s/<rid>/manuals` returning `{manuals: [{path, stem, summary}]}`) in `agents-plugin-tool/internal/wsdashboard/` plus dashboard template/frontend asset changes (`dashboard.tmpl`, `pages.go`, `page_routes.go`, `dashboard-drawer.js`, `dashboard-drawer.css`, `dashboard-stream.js`, and new modular Workpanel JS/CSS fragments). No MCP tool schemas, `/mcp` hello payloads, tracker wire formats, or on-disk store shapes change; older binaries remain unaffected.
- **4-Item Workpanel Scope (`(1727)=b`, `(1726)=a`):** Workpanel contains `Todo`, `Agenda`, `Notes`, and `Manuals` ONLY.
  - *Rejected:* Keeping `Tickets`, `Mailbox`, `Worktrees`, `Holders`, or `Review Ledger` in Workpanel (crowds narrow gallery columns and duplicates dedicated Ticket Map, Git, and bottom-bar Holders surfaces).
- **Graybox B Layout & `@container` 540px Breakpoint (`(1727)=b`, `(1731)=a`):**
  - **Upper always-visible Working Memory (`Todo` + `Agenda`):** `.wp-root` establishes `container-type: inline-size; container-name: wp`. At `>= 540px`, `.wp-memory` renders a 2-column grid (`Todo` left, `Agenda` right) with independent card scrollers, Todo progress bar + `done/total` badge, and Agenda expand/collapse-all control. Under `@container wp (max-width: 539px)`, `.wp-mem-seg` renders a full-width `[Todo | Agenda]` segmented control with counts, hides the inactive card, and compacts `#p-todo`'s header into a slim progress strip so `380px` columns stay uncluttered and preserve vertical height for the lower tab surface.
  - **Lower tabbed Reference Surface (`Notes` | `Manuals`):** A single scrollable card (`.wp-ref-card`) with a tonal tab switcher (`Notes` | `Manuals`):
    - **`Notes` tab (`GET/POST /s/<rid>/notes` via `handleNotes` in `notes.go`):** Renders 4-layer filter chips (`All`, `worktree`, `repo`, `clone`, `machine`), quick search (`key`, `body`, `layer`), `Muted` visibility toggle (`visible === false`), explicit `Refresh` button (`POST /s/<rid>/notes`, same-origin gated), priority badges (`P<n>`), relative age, and click-to-expand body. Respects `notesResponse.LocalOnly` (`!LocalViewer(r)`) so non-local LAN viewers only receive and display `wsnote.LayerRepo` with the `LocalOnly` hint.
    - **`Manuals` tab (`GET /s/<rid>/manuals`):** Backed by a new lightweight read-only endpoint `GET /s/<rid>/manuals` dispatched in `handleSessionRoutes` (`page_routes.go`) under `readMethod(w, r)`, matching the session-root read-only policy of `handleTicketIdeas` (`ticket_ideas.go`) and `handleFSList` (`fs_routes.go`). Resolves `d.index.Session(replyID)` -> `session.Registration.Project`, calls `wsdoc.ManualsList(session.Registration.Project)` on demand, and returns JSON `{manuals: [{path, stem, summary}]}` (`[]` when missing) with `Cache-Control: no-store` and `X-Content-Type-Options: nosniff` (safe for both local and non-local viewers; rejects `LocalBrowseAnchor`, invalid/unknown `replyID`, non-GET/HEAD with `405`, and unauthenticated callers with `401`). The UI filters rows client-side by `stem`/`path`/`summary` and opens any clicked manual via `window.WsPreview.open(path, { keep: true })` (matching `dashboard-ticketmap.js`).
  - *Rejected:* Graybox A (equal 2x2 or stacked 4-card grid that starves list scrollers at `380px`); stacking `Todo` and `Agenda` vertically below `540px`; pre-loading manuals on page render or SSE ticks (violates on-demand file-touch budget).
- **`.gal-rail` Ordering:** Preserves the owner-confirmed top-to-bottom rail sequence: `[Home ⌂] -> [User-pinned panels] -> [+ button] | separator (.gal-sep) | [System panels: Workpanel, Ticket Map, Git]`.
  - *Rejected:* Placing system panels above user pins or omitting the separator.
- **Legacy Retirement (`(1716)=a`, `(1717)=a`, `(1725)=a`, `(1731)=a`; transitional sequencing auto-confirmed):** Once all four live sections (`todo`, `agenda`, `notes`, `manuals`) render inside the `#bgal` Workpanel system page, Phase 2 retires the `Todo`, `Agenda`, and `Notes` (`#p-notes`) cards from `#drbody` / `#drcards` (their `panelTab` / `cardTab("notes")` registrations and the `notesLoad` call in `drApply`). `#p-mailbox` and `#p-tickets` are already retired by Track 2A; Phase 2 only verifies they are absent. `#drhandle` and a slimmed `#drbody` / `#drcards` sheet stay live transitionally, hosting only `#p-worktrees` (until Track 2B `261128-feat-ws-dashboard-gallery-git-page` migrates and retires it together with `#ghandle`) and `#p-holders` (until the follow-up `global-holders-popup` migrates it and removes `#drhandle` completely). Zero live functionality is stranded: `cardTab("worktrees")` / `cardTab("holders")` and the `wtLoad(); hdLoad();` calls in `drApply` stay. Keep `#ghandle` / `#gbody` untouched for Track 2B and `#shandle` / `#sbody` (`Ctrl+K`) operational. `drRoom()` (`--drhw`, `--shr`, `--ghr`), `drFill`, `DR_OPEN` `"panels"`, and `drfold` stay as they are, since the handle and sheet still exist.
  - *Rejected:* Retiring the whole sheet and `#drhandle` now (strands `#p-worktrees` and `#p-holders`, whose replacements have no landed ticket); gating Phase 2 behind Track 2B and a Holders-popup ticket (blocks an independently shippable migration on tickets that do not yet exist); hosting `worktrees` / `holders` as temporary extra Workpanel tabs (contradicts the 4-item scope decision).
- **`#r-panels` mounting contract:** the server-rendered `#r-panels` region (id preserved, `region("panels")` / `pages_render_test.go` pin) is rendered once, inside the Workpanel page's `.wp-memory` host, from Phase 1 on; the drawer's `todo`/`agenda` `panelTab` registrations are removed in the same phase so no orphan tabs or duplicate ids remain, while the drawer keeps its Notes, Worktrees, and Holders cards until Phase 2 (Worktrees and Holders beyond it). `panelInputFull` accepts only top-level `details.panel#p-*` rows and `mergePanelRows` requires `root.children` to equal the keyed order, so all `.wp-*` chrome (`.wp-head`, `.wp-mem-seg`, progress strip, expand-all control) sits outside `#r-panels`, which is a `display: contents` grid child; nothing is injected inside the region or its rows. The Todo `done/total` badge and `.wp-mem-seg` counts are derived from the region's `.chip` readers after each region update (as `panelTab`'s `count()` readers do today), replacing those readers when `panelTab` retires. The Workpanel page container selector is whatever landed Track 2A defines; Phase 1 starts by reading it and reconciles this contract with 2A's DOM.
  - *Rejected:* A second `#r-panels` copy for the Workpanel (id must be unique; double `panel-rows` patching); decorating rows inside the region (defeats keyed incremental patching).
- **Approval-wait signal moves to the Workpanel rail slot (owner-confirmed):** `drawerWait()` (`dashboard-drawer.js`) toggles `.wait` only on `#drhandle` / `#drfold` and returns immediately without `#drhandle`, so a full `#drhandle` retirement would silently drop the pending-approval cue. Preserve it: relocate `drawerWait` into `dashboard-workpanel.js` (global name kept so its sole caller `dashboard-board.js` `name === "tree" || name === "convlive"` branch and the test stubs of that name keep working), keep the same pending-approval selector (`#r-convlive .permwait, #r-tree .phase.permission, #r-tree .brow.perm`, excluding `.ag-source`), and toggle a `.wait` dot/pulse badge on the `.gal-rail` Workpanel system slot button (the direct replacement for `#drhandle`, created by Track 2A). The transitionally retained `#drhandle` keeps its own `.wait` class toggle (and `drfold` / `.dr-wait` styling) until `global-holders-popup` removes `#drhandle`; `drawerWait` therefore updates both hosts, tolerating an absent `#drhandle` so its removal needs no further change. The rail-slot badge uses the `--wb-ph-perm` / `--wb-perm-ink` tokens. `dashboard-companion-relay.js` only duplicates the selector for its own activity state and is unaffected.
  - *Rejected:* Dropping the signal and relying on conversation `.permwait` rows alone (loses the cue while the Workpanel/other pages are shown); a `#shandle` or bottom-bar host (not the retired handle's direct replacement; widens scope into Track 1 chrome).
- **Approved Visual Reference:** `ai-docs/assets/mockups/261128/gallery-workpanel-b/index.html` (with sibling `styles.css`, `data.js`, and `app.js`), covering Wide (`780px`), Narrow (`380px`), and Empty states across Dark and Light themes.

- **File-touch & I/O budget (`ai-docs/manuals/performance.md`):** `GET /s/<rid>/manuals` reads `ai-docs/manuals/*.md` via `wsdoc.ManualsList` strictly on demand when the `Manuals` tab is opened (never during `handleSessionPage`, SSE ticks, or timers). `Notes` preserves `handleNotes` on-demand worker caching (`GET /s/<rid>/notes`, `?wait=1`, explicit `POST` refresh; zero polling). `Todo` and `Agenda` reuse `#r-panels` (`regionPanels`) and `panel-rows` SSE incremental patching (`dashboard-stream.js` `panelInputFull` / `panelInputPatch`) without redundant DOM rebuilds.
- **Auth & viewer isolation (`notes.go`, `access.go`, `localhost_auth.go`, `page_routes.go`):** `GET /s/<rid>/manuals` stays bound to `session.Registration.Project` (no arbitrary `root=` query parameter). Authentication is not a handler concern: the mux-wide `accessGuard` (`access.go`) answers unauthenticated callers with `401` before dispatch (LAN without token: plain-text `401`; non-LAN remote or unauthenticated localhost: JSON `401 {"error":"login_required"}`); no `403` exists on this path. The route then returns `404` for `LocalBrowseAnchor` (`host0`), an invalid or unknown `replyID`, or an empty `Registration.Project`, and `405` on non-GET/HEAD via `readMethod`. This is the same guard and `readMethod` dispatch as `tickets/idea` and `fs/` routes, with one deliberate difference: `fs/` routes are exempt from the `host0` refusal in `handleSessionRoutes` (the host file browser), whereas `manuals` is not, since the host anchor has no project. `Notes` tab must preserve `notesResponse.LocalOnly` (`wsnote.LayerRepo` only for non-local LAN viewers) and same-origin protection on `POST /s/<rid>/notes`.
- **Visual & Responsive Parity (`ai-docs/manuals/dashboard-style.md`):** Borderless Material tonal surfaces (`--wb-bg`, `--wb-card`, `--wb-muted`), `tabular-nums` for counts/priorities/ages, Dark & Light parity, `@container wp (max-width: 539px)` layout switching, and `0px` horizontal overflow (`scrollWidth <= clientWidth`) at `380px` and `780px`.
- **Modular JS/CSS hygiene:** Isolate new Workpanel styles and controller logic in dedicated embedded files (`dashboard-workpanel.css`, `dashboard-workpanel.js` registered in `pages.go`) rather than expanding `dashboard.js` or `dashboard-drawer.js`.
