# Werkschaft Companion Engine v2: Full Timing Assetization, Hybrid Global Rail Observation, Articulated Drag & Resize UX

## Background

Live dogfood testing of `261122-feat-ws-companion-shell-engine` on Werkschaft (2026-11-22) exposed both concrete relay/rendering bugs and high-leverage architectural gaps:

1. **Typing lock & ghost drone/mail events (`dashboard-companion-relay.js`):**
   - `terminal` (`relay.js:11`) omits `"holding"`, so idle-waiting alive subagents (`pageview_hud.go:225`) count toward `running > 0`. Combined with `relay.js:182` (`phase === "replying" || phase === "tool" || running > 0 -> "streaming"`), the character stays stuck in `pose: "typing"` even when nothing is active, masking `thinking` and `user.typing`. Naive insertion of `"holding"` into `terminal` would instead misclassify a `running -> holding` transition as terminal completion (`relay.js:109`), emitting a ghost `subagent.done`; activity and liveness must be tracked separately.
   - `subagent.done` is emitted independently from `agentNodes()` (`relay.js:109`) and `archived()` (`relay.js:163`) with potentially diverging keys, firing duplicate drone returns.
   - Canonical peer mail renders as `<article class="mail-block" data-entry="..."><details class="mailline recv|sent">` (`dashboard.tmpl:391`), while board nudges render as `<details class="mail-notification" data-mail-wake="...">` (`dashboard.tmpl:382`) and unmatched ordinary peer mail renders as `<details class="mail-notification">` without `data-mail-wake` (`conversation_board_nudge_test.go:194-212`). The relay (`relay.js:164-165`) conflates board nudges with peer mail and misses `mail.send`, and `visibilitychange` can race `reconcile(true)` against `showRegions()`, replaying stale entries on tab return.
   - `thinking_ponder` plays `coffee` + `…` for only `1.7 s` before dropping into plain `passive.thinking`; `user.typing` only activates when `idle`.
2. **Hardcoded timing & motion curves (`dashboard-companion-compositor.js`, `dashboard-companion-scenarios.js`, `dashboard-companion-stage.js`):**
   - `stageEffects`, `propMotion`, keyframe interpolation (linear only), and drag pendulum constants are hardcoded in JS rather than assetized in `pack.json`.
   - Stage prop motion currently derives solely from `prop.data.behavior` (`stage.js:238-246, 280-294`), so a single `mail` prop cannot play `hand-liftoff` on `mail_send` and `bonk-from-edge` on `mailbox_bonk` without a beat-level `prop.motion` selector.
   - Drone flight (`1.05 s`/`1.25 s`) and mail incoming flight (`337 ms`) are far too fast to read or to make eye tracking noticeable; `default/drone.png` renders as a flat squished box; `default/pack.json` draws `grab.png` (`z: 25`) over `stand.png` (`z: 20`).
3. **Single-session blind spot & fixed small size:**
   - Companion only sees the active iframe; approvals, new asks, failures, and completed turns in other sessions go unnoticed even though the outer shell already receives reconciled `"rail"` stream snapshots (`dashboard-stream.js:511-532`) for every live session row (`.rs[data-rid]`) with zero extra I/O.
   - Character canvas size is fixed (~`94 px` docked on a `260 px` rail, capped at `96 px` collapsed) with no way for users to scale the doll to their preference.

## Decisions

Owner decisions locked via whiteboard `55=a`, `56=a`, `57` note, timing-assetization confirmation (2026-11-22 13:29 KST), and `58=a`:

1. **Assetize-First Timing Grammar & Explicit Public Bounds (`ws-companion/v1`, pure T0 non-rejecting passthrough):** Move currently hardcoded timing, easing, whole-body stage curves, prop trajectories, drag physics constants, and passive state mappings into declarative `pack.json` dictionaries with engine starter defaults so future art packs tune every beat without JS changes:
   - **Safety-only Go validation + non-rejecting linter + JS runtime sanitization (zero v1 rejections):** None of the v2 timing/physics/anchor fields introduce asset paths, URLs, or security surfaces. Preserve the parent epic's unknown-field passthrough invariant (`261122-epic-werkschaft-lead-companion.md:39-45`): `validateCompanionManifest` adds **zero** new hard rejections for `ws-companion/v1` manifests (so any manifest accepted by the old Go reader — even with opaque colliding keys such as `"passive": "custom"` or `"easings": 123` — remains 100% loadable). Add a non-rejecting Go diagnostic linter (`lintCompanionTiming`) checking the exact bounds below for unit tests/tooling without failing load, and enforce those exact same bounds defensively in the JS runtime (`compositor.js`, `scenarios.js`, `stage.js`) by ignoring malformed or out-of-range extension entries and falling back cleanly to built-in starter defaults.
   - **`easings`:** Map of identifier (`1..64` chars, `^[a-zA-Z0-9_-]+$`) → finite 4-tuple `[x1, y1, x2, y2]` with `0 <= x1 <= 1`, `0 <= x2 <= 1`, `-4 <= y1 <= 4`, `-4 <= y2 <= 4`. Built-in presets (`linear`, `easeIn`, `easeOut`, `easeInOut`, `anticipate`, `overshoot`, `snapBounce`), declared `easings` names, and inline 4-tuples are accepted on `motions[].keyframes[].ease`, `stageEffects[].keyframes[].ease`, and `propMotions[].keyframes[].ease`.
   - **`stageEffects`:** Map of identifier → `{ keyframes: [...] }` (`1..64` frames). Each frame has finite nondecreasing `p ∈ [0, 1]`, optional finite `lift ∈ [-2, 2]`, `tx ∈ [-2, 2]`, `sx ∈ [0.1, 3]`, `sy ∈ [0.1, 3]`, `rotDeg ∈ [-180, 180]`, and optional `ease`. Built-in starters (`stay`, `hop-bounce`, `double-hop`, `squash-pop`, `anticipate-launch`, `settle-sigh`) live in this data table with **"끙---차!" (crouch anticipation → crisp snap → slight overshoot → settle)** beats; packs may override or add named stage effects.
   - **`propMotions` & per-beat `prop.motion` selector:** Map of identifier → `{ keyframes: [...], edge?: "away"|"left"|"right", recoil?: { start, peak, end, lift?, angle? } }` (`1..64` frames). Each frame has finite nondecreasing `p ∈ [0, 1]`, optional finite `along ∈ [-2, 3]`, `arcY ∈ [-3, 3]`, `offsetX ∈ [-3, 3]`, `offsetY ∈ [-3, 3]`, `scale ∈ [0, 4]`, `rotDeg ∈ [-720, 720]`, `alpha ∈ [0, 1]`, and optional `ease`. Optional `recoil`: `0 <= start < peak < end <= 1`, finite `lift ∈ [-1, 1]`, `angle ∈ [-1.5, 1.5]`. Built-in starters (`attach`, `orbit`, `hand-liftoff`, `arc-to-landmark`, `bonk-from-edge`, `burst`) live in this data table. Scenario beats may specify `prop: { id, motion?, action?, from?, to? }`; effective motion resolves as `beat.prop?.motion || prop.data.behavior || "attach"` (and attached-to-body rendering in `setBeat` checks that effective motion, not only `prop.data.behavior`), allowing one `mail` prop to play `hand-liftoff` on `mail_send` and `bonk-from-edge` on `mailbox_bonk` while preserving legacy `prop: "mail"` packs.
   - **`physics.drag` & Articulated Per-Joint Inertia (No `prop-grab`):** Remove `prop: "grab"` from `drag_dangle` (and from `default/pack.json`). Pass live `physics` (`{ swing, swingVel }`) from the stage spring integrator into `view.render(seconds, gaze, physics)`. Optional `physics.drag` finite numeric bounds (and defaults): `stiffness ∈ [5, 300]` (`42`), `damping ∈ [0.5, 40]` (`7.5`), `impulse ∈ [0, 0.5]` (`0.07`), `maxDeg ∈ [0, 45]` (`18`), `bodyFallbackScale ∈ [0, 1]` (`0.65`). Optional per-layer (pose layers, `head`, `hair.back`) finite bounds: `swingWeight ∈ [-2, 2]` (default `0`; recommended artistic range `0.15–0.90`) and `swingLag ∈ [-0.5, 0.5]` (default `0`; recommended `0.03–0.14`). When a pose declares per-layer `swingWeight`, rigid whole-body slab rotation is disabled in favor of articulated per-joint sway; packs without `swingWeight` keep the gentle `bodyFallbackScale` pendulum fallback.
   - **`handAnchor` & Visible Prop Gaze Tracking:** Optional `handAnchor: [x, y]` on gestures and poses (`0 <= x <= canvas[0]`, `0 <= y <= canvas[1]`; resolution: gesture → pose → `[canvasW * 0.5, canvasH * 0.48]`) so `subagent_dispatch`, `subagent_return`, and `mail_send` launch/land props visibly from cupped hands (`gesture: "cup_hands"`, falling back to `stand`) on `hand-liftoff`. Optional `head.gazeTiltDeg ∈ [0, 30]` (default `1.5`) and `head.propGazeTiltDeg ∈ [0, 30]` (default `6.0`) tilt the head alongside faster `prop:*` iris pan so eyes and head clearly track slower flying drones (`~2.4 s` / `~2.2 s`) and letters (`~2.0 s`).
   - **`passive`:** Optional map keyed by `{ idle, doze, user_typing, typing_user, thinking, tool, replying, streaming, permission, error }`, each value an object with optional safe string fields `{ pose, gesture, expression, gaze, stage, fx, prop }`. `user_typing` and `typing_user` alias each other; legacy `streaming` merges into `replying` when `replying` is not explicitly overridden.
2. **Hybrid Cross-Session Observation & Explicit Signal Arbitration (`56=a`):**
   - **Reconciled Snapshot Seam (`dashboard-stream.js:511-532`):** Observe `#rail` at the exact reconciled snapshot seam where `railAttention.observe(q(".rs", railFrag), rid, railBaseline)` runs (passing `(railFrag, activeRid, railBaseline)` into `WsCompanion.observeRail(...)`, plus one silent `baseline=true` hydration from mounted `#rail` on shell mount). This captures transient asks/completions even while the tab is hidden or during rail drag/rename and inherits `railBaseline` on initial connect and reconnect. Resolve the `rail-alert` landmark rect lazily from the mounted `#rail .rs[data-rid="..."]` (falling back to the visible parent `.rs` when a child row is collapsed inside `.rkids`).
   - **Companion-Specific Rail Filtering:**
     - **Approvals:** inspect every live `.rs[data-rid]` (including child rows inside `.rkids`) for `[data-ap]`, keying each approval by its own child/row `data-rid` (never double-counting parent `.kap` rollups with child `[data-ap]`; if only `.kap` is present on a parent without visible child `[data-ap]`, fall back to the parent `rid`).
     - **New asks:** parse `data-asks` as whitespace-separated ID sets (`pageview_rail.go:234`, `rail.js:521-524`) and detect set additions (`newIds \ prevIds`) after silent baselining.
     - **Failures:** live rows carrying `.hb.err`.
     - **Background turn completion (`global.session_done`):** mirror `rail.js:585-603` (`top && prev.top && live && prev.busy && prev.active && !busy`), PLUS exclude `id === activeRid` (background sessions only) AND exclude rows entering `[data-ap]` or `.hb.err` in the same snapshot.
     - **Global working count:** non-active live rows with `data-active="1"` (not in `[data-ap]` / `.hb.err`).
   - **Arbitration & Deduplication Priority:**
     - **Passive posture priority (highest wins):** `permission` (active session, else any global `[data-ap]`) > `error` (active session, else any global `.hb.err`) > `user_typing` (active session typed within `2.5 s` while active session is `idle` or `thinking`) > `thinking` (active session) > `tool` (active session) > `replying` (active session) > global soft fallback (`tool` when active session is `idle` or on home/settings routes while another live `#rail` row has `data-active="1"`) > `idle` > `doze`.
     - **One-shot priority (highest wins via `scenarioRunner`):** `user.drag` (`100`) > `session.error` (`70`) > `ask.open` (`65`) > `session.celebrate` (`60`) > `mail.recv` (`57`) > `subagent.done` (`56`) > `subagent.spawn` (`55`) > `mail.send` (`54`) > `global.session_done` (`52`) > `session.compacted` (`48`) > `user.poke` (`45`) > `route.switch` (`25`) > `idle.long` (`5`).
     - **Same-snapshot & cross-source deduplication:** Current-session asks and approvals are deduplicated between `#rail` and the iframe relay by canonical key (`ask:<rid>:<id>`, `perm:<rid>`), preferring the iframe's `"whiteboard-ask"` landmark when mounted and falling back to `"rail-alert"`. When multiple global urgent events appear in a single `#rail` snapshot, emit at most one winning event per snapshot in strict order: `global error` (`70`) > `global approval` (`65`) > `global new ask` (`65`) > `global.session_done` (`52`), targeting that row for `rail-alert`. Equal-priority simultaneous active + global signals prefer the active session.
3. **Relay Fixes, Legacy Hook Preservation & Updated Scenario Catalog (P1–P6, S1–S11):**
   - **Separate subagent `active` vs `alive` & safe turn attribution (`pageview_hud.go:214-228`, `relay.js:98-132, 162-163`):** Keep `terminal = new Set(["idle", "ended", "closed", "done", "failed"])` unchanged (do NOT add `"holding"` to `terminal`). Track `alive = !terminal.has(state) && !ended.has(id)` and `active = alive && state !== "holding"`. Only `active` children count toward `running`.
     - **Spawn (`holding` excluded, matching manual S2):** Baseline records all initially present children with `spawned: true`. Post-baseline, emit `subagent.spawn` **only** when a child enters `active === true` and `!info.spawned` (setting `spawned = true`); a child first sighted already in `holding` records `spawned = false` and emits zero spawn unless/until it enters `active`.
     - **Completion (`subagent.done`), `background_exit` exclusion & bidirectional turn reconciliation:** Retain the existing `row.dataset.wakeCause !== "background_exit"` exclusion on archived `.mailline.recv.agent-note`. Reconcile BOTH arrival orders (tree-before-entries and entries-before-tree, `dashboard-stream.js:467-485`) while preventing cross-turn duplicate replay using per-child state `{ reportedCurrentTurn, awaitingReport, lastDoneMs, turnStartedMs, doneSeq }`:
       - When `active` transitions `false -> true` post-baseline (new/resumed turn): reset `reportedCurrentTurn = false`, record `turnStartedMs = now` (leaving `awaitingReport` intact only if a prior turn never received its report).
       - **Early report (entries arrive before HUD leaves `running`):** When `archived()` sees an attributable `child-report`/`agent-note` (`id = reportIdentity(row)`, non-empty) while `info.active === true`: ignore if its timestamp `rowMs` (from `time[data-ms]` when present) predates `info.lastDoneMs` (stale duplicate); otherwise if `!info.reportedCurrentTurn`, emit `subagent.done` once (`canonical + ":" + ++info.doneSeq`), set `info.reportedCurrentTurn = true`, `info.awaitingReport = false`, and update `info.lastDoneMs = rowMs || now`.
       - **HUD `running -> holding` (`previous?.active && !active && alive`):** If `info.reportedCurrentTurn` is already `true`, emit nothing and keep `awaitingReport = false` (already reported early); otherwise set `info.awaitingReport = true` (no HUD emit yet).
       - **Normal-order report (HUD moved to `holding` first):** When `archived()` sees an attributable report while `info.active === false`: emit `subagent.done` once (`canonical + ":" + ++info.doneSeq`) ONLY if `info.awaitingReport === true` (and `rowMs` does not predate `info.lastDoneMs`), clearing `info.awaitingReport = false`, setting `info.reportedCurrentTurn = true`, and updating `info.lastDoneMs`. Duplicate rows for the same turn see `awaitingReport === false` and are suppressed.
       - **HUD terminal exit (`previous?.alive && !alive`):** Emit `subagent.done` once ONLY if `(previous.active && !info.reportedCurrentTurn) || info.awaitingReport`, then set `info.awaitingReport = false` and `info.reportedCurrentTurn = true`. (Closing an already-reported `holding` child emits nothing.)
       - **Ambiguous / short-lived reports:** If `reportIdentity(row) === ""` (ambiguous shared label), suppress. If `id` is non-empty and not in `agents` (short-lived child completed between polls), insert a tombstoned entry `{ canonical: id, alive: false, active: false, spawned: true, reportedCurrentTurn: true, awaitingReport: false, lastDoneMs: rowMs || now, doneSeq: 1 }` and emit once (`id + ":1"`), suppressing any second archive row for that child.
   - **Canonical peer mail & single/grouped board nudge filtering (`dashboard.tmpl:382, 391`, `conversation_mail_wake.go:189-195`, `conversation_board_nudge_test.go:27-49, 194-212`):**
     - Expose the existing board-nudge classification in `dashboard.tmpl:382` as `{{if .BoardNudgeSummary}} data-board-nudge="1"{{end}}` on `<details class="mail-notification" ...>` (separate from `data-mail-wake`, which remains grouped-only so `conversation_board_nudge_test.go:27-49` passes unchanged).
     - Classify each keyed `[data-entry]` row together with its direct child:
       - `mail.recv`: `article.mail-block` containing `:scope > details.mailline.recv`, OR `.mail-notification:not([data-board-nudge]):not([data-mail-wake])` (ordinary unmatched peer mail), OR standalone `.mailline.recv:not(.agent-note):not(.child-report):not(.agent-card)`. Explicitly exclude `.mail-notification[data-board-nudge]` (both single and grouped board nudges), `.mail-notification[data-mail-wake]`, `.child-report`, `.agent-note`, and `.agent-card`.
       - `mail.send`: `article.mail-block` containing `:scope > details.mailline.sent`, OR standalone `.mailline.sent`.
       - `session.compacted`: `.sysline.compaction:not(.fail)`.
   - **Activity split & exact legacy `session.streaming` edge (`relay.js:10, 174-209`, `scenarios.js:12-15, 53-85`):**
     - Split `activity` into `"permission" | "error" | "thinking" | "tool" | "replying" | "typing_user" | "idle"`: `thinking` is never masked by `running > 0`; `typing_user` surfaces when the user typed within `2.5 s` during either `idle` or `thinking`.
     - Emit `"session.tool"` and `"session.replying"` on their own activity transitions (`act !== lastActivity`), AND preserve the exact legacy `"session.streaming"` rising edge independently in `dashboard-companion-relay.js`: compute `legacyRunning = Math.max(aliveCount, subdeepCount)` (preserving both `data-subdeep` and the original `!terminal.has(state)` child count) and `streamingNow = !wait && phase !== "permission" && !failed && (phase === "replying" || phase === "tool" || legacyRunning > 0)`, emitting `"session.streaming"` strictly when `!lastStreaming && streamingNow` (so legacy pack subscriptions keep their exact original trigger inputs without double-firing on `tool -> replying`, while the new v2 posture uses `active` children only and never lets `running` mask `thinking`).
     - Preserve legacy starter IDs **`mailbox_bonk`** (S5, `on: "mail.recv"`) and **`working_tatata`** (`on: "session.replying"` — with `passive.streaming` overrides merging into `passive.replying` when `passive.replying` is unset).
     - Keep `passive.thinking` showing `gesture: "coffee"` + `half_lid` + `gaze: "up"` + ambient `ponder` (`…`) for the entire thinking duration; reserve `typing` pose strictly for `replying` and use `stand` + `focused` + `scan` for `tool`; cycle gentle idle variety on extended idle.
     - Fix the `visibilitychange` baseline race so hidden-tab region swaps (`showRegions()`) complete before `reconcile(true)` clears `baseline`.
