# Git Page: Single Full-Width Graph Panel, Synthetic UNSTAGED Row, Icon Toolbar, and Worktrees Popover

## Background

The gallery's Git page (`#gitpage`, rendered by `{{define "gitpage"}}` in `agents-plugin-tool/internal/wsdashboard/assets/dashboard.tmpl`, driven by `assets/dashboard-gitpage.js` and `assets/dashboard-git.js`, laid out by `assets/dashboard-gitpage.css`) is a three-region page: the commit graph card `#glog` on the left, the Changes card `#gpanel` (file list `#gfiles`) top-right, and the Worktrees card `#wtcard` bottom-right. The `.gp-regions` grid gives the graph 52fr of the width and the two side cards the other 48fr; below a 720px container width the same three cards collapse into the `.gp-tabs` tab bar (Graph / Changes · Diff / Worktrees).

The problem shows on desktop with a narrow gallery (the portrait-ish `#bgal` column, the Git page host `#gitdock`): the graph's subject column is squeezed to roughly 6-8 characters because the graph owns only about half of an already narrow column, while Changes and Worktrees permanently occupy the other half even though most of the time the working tree is clean or the pool list is not needed. The commit subject is the most useful column of the history and is the one that gets sacrificed.

This ticket makes the commit graph the page's only panel at every width, turns the other two surfaces into on-demand affordances that reuse existing components, and compacts the top strip so it costs less width:

- Working-tree changes become one synthetic `UNSTAGED` row inside the graph (only when the tree is dirty) that opens the existing commit window (`gwin`) on the working tree.
- Fetch / Pull / Push become icon-only buttons.
- Worktrees move into an anchored popover opened from a compact toolbar button. The page showing must not read or walk the pool until the Worktrees popover opens.

## Decisions

Owner-settled (no open decision queue remains):

- **`(1748)=a` - Reuse the commit window for working-tree changes.** Clicking the synthetic `UNSTAGED` row opens the existing commit diff popup (`gwin`, built by `gwBuild`, filled for the working tree by `gwWorktree` in `dashboard-git.js`), with its Staged / Unstaged / Untracked sections and diff viewer preserved. No separate split pane or drawer is added. In worktree mode the `gwin` header (`.gw-acts`, next to the copy-hash and close buttons) gains a Refresh icon button that re-reads the working-tree snapshot in place, so the user does not close and reopen the window to see new changes (full contract below). The Refresh button is hidden in commit mode, as the copy-hash button is hidden in worktree mode today. *Rejected:* a separate split pane or slide-in drawer for the changes list.
- **`(1749)=a` - One synthetic `UNSTAGED` row, only when dirty.** The graph renders exactly one synthetic row when `staged + unstaged + untracked > 0` in the latest status read (`gitLast`), placed directly above the `HEAD` commit's row, joined to `HEAD`'s node by a dashed `.cont` connector. It is absent when the tree is clean. Clicking it (or Enter / Space on it) opens `gwin` through `gwWorktree`.
- **`(1750)=a` - Straight to `ready/`.** The ticket is implemented directly, reusing the existing `dashboard-git.*` and `dashboard-gitpage.*` components; no separate mockup is produced. Visual decisions follow `ai-docs/manuals/dashboard-style.md` and the existing graph/strip look.

Auto-settled technical decisions (sage-review settlement under `pref.ticket-settlement-autonomy`):

- **Compatibility tier: T0 transparent.** Pure frontend change: `dashboard.tmpl`, `dashboard-git.js`, `dashboard-gitpage.js`, `dashboard-git.css`, `dashboard-gitpage.css`, one new sibling script `dashboard-gitpage-wt.js` (registered in `pages.go`), and i18n keys in `agents-plugin-tool/internal/wsi18n/tables/*.json`. Zero MCP tool schema, wire field, store, or HTTP route changes: the page keeps reading `GET /s/<rid>/git/status`, `git/log`, `git/commit/<oid>`, `git/worktree/diff`, `worktrees` (`?no_size=1` and the full scan), and `review-ledger` exactly as today. No on-disk format changes.

- **Synthetic row insertion in `glDraw` (`dashboard-git.js`).**
  - **Slot:** the row is inserted at `HEAD`'s loaded index `headIdx = gl.head ? glFind(gl.head) : -1` - never `glFind("")`, which matches index 0 (`oid.indexOf("") === 0`) on an unborn HEAD. `HEAD` is not assumed to be row 0, because other branch tips or detached worktree HEADs can sort above it. Rows from `headIdx` downward shift by one row slot in `glY`; every lane segment, node circle, the `head` ring, the frontier ring, the trailing `.cont` run into `.glmore`, and the SVG height (which includes `GL_MORE`) use the shifted slot, so no lane breaks or leaves a dangling stub. A lane segment that leaves the row above `HEAD` and ends at `HEAD`'s row or below spans the synthetic row's slot.
  - **Incoming-lane geometry when `headIdx > 0`:** the synthetic node is hollow (dashed outline, in the existing `.glsvg` style language). If no solid through-lane occupies `HEAD`'s column at the synthetic slot, the node sits in `HEAD`'s column with a vertical dashed `.cont` connector into `HEAD`'s node (`HEAD`'s lane colour). If a solid through-lane from above occupies `HEAD`'s column at the synthetic slot, the node sits on a dedicated rightmost stub lane (`gl.width` as the next free column, so the column count and `--gw` grow by one) with a dashed `.cont` elbow into `HEAD`'s column at the `HEAD` slot, so it never sits on an unrelated commit edge. When `headIdx < 0` (`HEAD` missing from the loaded page, or unborn), the row is drawn at slot 0 as a standalone hollow node with no connector.
  - **Empty-log and loading guards:** `glDraw` must not return early on an empty log while the tree is dirty (today `if (!n) { ... "js.git.log.empty" ...; return; }` would hide the row); the empty-state line and the `UNSTAGED` row coexist. The empty-log message is gated on `gl.loaded && !gl.busy`, so an early `gitDraw` before the first `glLoad` finishes never flashes `js.git.log.empty`. `glFail` and `glLoad`'s loading branch (`js.git.log.loading`), which both clear `glrows`, preserve or redraw the `UNSTAGED` row instead of wiping it. The `glcount` chip counts commits only, never the synthetic row.
  - **Minimal DOM updates (`performance.md`):** `gitDraw(v)` computes a compact dirty signature `staged|unstaged|untracked|add|del|truncated` and compares it with the previous one. Unchanged: no-op (no DOM work, no scroll reset). Counts changed while dirty before and after: patch the existing `.glr[data-worktree]` row in place (label, badges, `aria-label`, `title`), preserving `.sel` and focus. Full `glDraw` runs only on clean-to-dirty and dirty-to-clean transitions (the only cases that change the slot layout). A status read that fails keeps the previous row.
  - **Identity, handlers, a11y:** the row is `.glr` with `data-worktree="1"` and no numeric `data-i`, so it can never index `gl.commits`; it carries `role="button"`, `tabIndex = 0`, and a descriptive `aria-label` (total and per-group counts). The `glrows` click and keydown handlers branch on `data-worktree` first and call `gwWorktree(<first non-empty side>, 0)` (side order Staged, Unstaged, Untracked); today they do `gl.commits[+row.getAttribute("data-i")].oid` and would throw on the synthetic row. In `glTip`, the early return for a row with no commit (the synthetic row) calls `glTipHide()` so a stale commit tooltip clears on hover; the synthetic row's own `title` carries the count breakdown. `glRowEl(i)` is keyed by `data-i` (`.glr[data-i="..."]`) and is unaffected.
  - **Cells and counts:** the row keeps empty `.gla` / `.glt` / `.glh` cells so the narrow container-query column templates (`.glr` grids in `dashboard-gitpage.css`) stay aligned. The subject cell shows the localized `UNSTAGED` label and the total dirty count badge, with compact per-group chips (Staged / Unstaged / Untracked) when the subject column has room and always in the tooltip; the line delta (`+add -del`, previously `#gpsum`) goes in the tooltip. Counts reuse the existing `.chip` / `.ggrp` look. When `v.truncated` is true (the server lists at most 300 files per group) the counts render as `300+` style (`js.git.truncated` wording reused for the tooltip).
  - **Selection and focus:** `gw` gets an explicit worktree-mode flag (for example `gw.worktree`), set by `gwWorktree`, cleared by `gwOpen` and `gwClose`. `gwSel` (today toggles `.sel` by `c.oid === gw.oid`) and the `glDraw` row builder (today computes `.sel` from `gw.oid`) both honour it, because `gwWorktree` sets `gw.oid = ""`. On `gwClose`, if `gw.lastFocus` is no longer in the document (the row was rebuilt), focus falls back to `glrows.querySelector('.glr[data-worktree]')`, else `#glrows`.

- **`gwin` Refresh button (complete contract).**
  - Placement and visibility: an icon button (`.ia`, Lucide `refresh-cw` via `luIcon`) in `.gw-acts`, visible only while `gw.worktree` is set. Add `.gwin .ia[hidden] { display: none; }` to `dashboard-git.css` (mirroring `.gwin .idcopy[hidden]`), because `.gwin .ia` sets `display: inline-flex` and would otherwise leak the button into commit mode. Do not call `gw.win.focus()` on the Refresh path, so keyboard focus stays on the Refresh button. ## Phases

- **`glFail` keeps the synthetic row.** It clears the commits and shows the error next to the row.
- **The hash column hides at <=460px**, so the subject column keeps priority.
