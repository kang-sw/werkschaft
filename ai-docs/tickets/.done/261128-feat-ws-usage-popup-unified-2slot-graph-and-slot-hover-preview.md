# Plan Usage Popover Rework: Unified 2-Chart Graph View, Compact Slot Rows, and Inactive-Slot Hover Preview

## Background

The plan-usage popover (`agents-plugin-tool/internal/wsdashboard/assets/usage.js`, `usage.css`) grew one 5-hour and one 7-day chart card per provider column (Claude, Codex, and two Antigravity model groups, plus Werk OpenAI and OpenRouter detail cards), and the multi-account slot switcher landed afterwards as a separate `.usage-accounts` block at the bottom (`drawAccounts`). With Track 1 (`261128-feat-ws-dashboard-ide-shell-overhaul`) moving `.usage-toggle` into the bottom-right status bar as an upward-opening popover, the owner reviewed an interactive mockup (`ai-docs/assets/mockups/261128/usage-popup-rework/index.html`, with sibling `styles.css`, `app.js`, `mock-api.js`) and settled a rework that keeps the graph view the owner likes while folding account switching into the same surface:

- the up-to-eight per-provider charts become **two unified charts (5H and 7D)** shared by every harness;
- each provider/slot becomes one compact row with inline slot pills, so a slot switch is one click on the row that shows its usage;
- hovering an **inactive** slot pill previews that slot's last cached usage on the same charts, without any request, probe, or file read (an owner request added after the mockup; the mockup does not depict it).

A restart-shaped test passes non-trivial `Harnesses`, starts with a non-default active slot, and then switches. Rejected: assuming `"default"` until the first account change.

Rejected: rewriting the whole `plan-usage` source through `SetUsageLatestEntries`.
  - **Sample partitioning (technical).** The active slot's projection (`projectPlanUsageHistory`) keeps samples stamped with the active slot id plus unstamped legacy samples, and drops samples stamped for other slots, with the neighbor link taken inside that filtered series, so once stamped samples exist the first stamped point after a switch does not join the previous slot's last stamped point. One accepted artifact: on the first switch after an upgrade the previous slot's history is entirely unstamped legacy, so that first stamped point can still link to the old slot's last legacy sample (one-time per install, not wrong data); the test asserts the stamped-only case. A slot's preview `samples` are only its own stamped samples; an upgraded install therefore previews an inactive slot as a pin and stats from its snapshot with no curve until new stamped samples exist. The `<provider>` token of the persisted key comes from the stashed entry's `Harness` value, never a new name literal.
  - *Technical:* samples are attributed to the slot that is active when they are recorded (the existing `claudeSlotID` / `gptSlotID` assumption; `wslive.Snapshot` carries no slot id). `handlePlanUsage` calls `pushClaude` for every session's retained snapshot on each request (`plan_usage.go:696-702`), so any session still bound to the previous slot whose last limits are newer than the restored entry's `AsOf` (idle sessions as well as queued ones) can replace the restored windows on the first request and be stamped with the new active slot. That limitation already exists in the active-slot numbers and is not changed here (out of scope below); the phase Result records whether it was observed.
  - *Rejected:* polling or probing inactive slots for preview data (violates the zero-polling rule and would spend provider quota); reading a file on hover (`performance.md`); keeping the old evict-on-switch behavior (the numbers vanish until the next push).
- **Additive `slotPreviews` in `/rail/usage?history=1` (technical shape, owner-confirmed content).** `handlePlanUsage` adds, only when `history=1`, `slotPreviews: { "<harness>": { "<slotID>": { asOf, windows: [ {kind, percent, resetsAt, asOf} ], samples: [ planUsageSample ] } } }` for every non-active stashed slot. `windows` pass through `currentUsage` at response time (an expired window is dropped); a slot with no live window is omitted, which the page reads as "no usable cache". `samples` are the slot's own history samples limited, like `projectPlanUsageHistory` (`plan_usage_history.go:641-688`), to those that `trend()` can draw for the slot's cached windows (same `resetsAt`, plus the neighbor sample), so the member stays small. The member is built from memory (the stash plus the already memoized history), with no extra file read.
  - *Rejected:* a separate `/rail/usage/slot` endpoint hit on hover (extra request per hover); returning all history samples for every slot (unbounded payload).
- **Frontend: inactive-slot hover preview (zero requests, zero file touches on hover).** Hovering an inactive slot pill draws, from the already loaded `slotPreviews`, a dashed preview curve and a preview pin labeled with its cached age (for example `Cl·Work · 12분 전`) plus a callout on both unified charts, dims the active slot's curve to a faint baseline, and replaces that row's `5H` / `7D` stats and mini-Gantt with the slot's cached values. A slot with no usable cache (never visited, or all cached windows expired) shows the subtle callout `캐시 없음 · 클릭해 전환 후 조회`. Hover only toggles classes and attributes on nodes pre-built when `slotPreviews` loads; leaving the pill restores the active view. Clicking still switches.
