# ws-Managed Compaction (Harness-Agnostic wscompact, External-Harness Session Rotation, and Conditional tools/list Schema)

## Background

Today, hosted leads split compaction across two incompatible worlds:

1. **Builtin `werk` leads** perform ws-managed self-compaction: the lead passes 7 structured carry-forward prose fields plus optional `reread` paths to `ws/compact(lead_summary)` (`agents-plugin-tool/internal/wscompact/summary.go:10-83`), and `agents-plugin-tool/internal/werk/compaction.go:62-126` plus `agents-plugin-tool/internal/werk/lead_compaction.go:10-72` assemble a deterministic markdown checkpoint (carry-forward prose, bounded `reread` file contents up to 40 KiB, recent `## Dialog` tail up to 40 KiB, active ticket/playbook references, and live `CompactionState` children/exec-job snapshot), commit an explicit `wsaudit.KindCompaction` checkpoint (`agents-plugin-tool/internal/wsagent/werk_loop.go:244-261`), and reset the transcript to `[checkpoint]` in place.
2. **External hosted leads (`claude`, `codex`, `agy`)** are currently blocked from using `lead_summary` by the `leadSummaryCompactor` type gate in `agents-plugin-tool/internal/wsagent/compaction.go:117-123` (`"lead_summary is only available for a builtin lead compacting itself"`). They must rely on each harness's opaque native `/compact` command (`wsagent/compaction.go:455-462`), which cannot preserve ws-structured carry-forward state or `reread` files, behaves inconsistently across harnesses, and on `agy` emits no explicit compaction event (forcing estimated `usage_drop` inference in `agents-plugin-tool/internal/wsagent/audit_agy.go:121-127,258-300`).
3. Meanwhile, `agents-plugin-tool/internal/mcp/compaction.go:59-67` unconditionally attaches `wscompact.LeadSummarySchema()` to the `compact` tool definition in `tools/list` for every session—costing 712 bytes of extra schema tokens (`agents-plugin-tool/internal/mcp/compaction.go#L59-L67`, `agents-plugin-tool/internal/wscompact/summary.go#L35-L51`) even on sessions using native compaction—while the shared checkpoint assembly logic remains trapped inside `internal/werk/`.

This ticket lifts the checkpoint assembly engine out of `internal/werk/` into a harness-agnostic `internal/wscompact/` package, extends hosted-lead ws-managed compaction to `claude`, `codex`, and `agy` via native session rotation (preserving ws session identity, ring history, audit stream, and children), adds a two-stage fallback for triggers without `lead_summary`, and gates `tools/list` exposure of `lead_summary` per session under a single T0-compatible server acceptance contract.

## Decisions

### 1. Single Server Acceptance Contract + Conditional `tools/list` Schema View (Owner-Confirmed `(1537)=a`)

- **Server acceptance contract (always permissive, never knob-gated):** `handleCompact` (`agents-plugin-tool/internal/mcp/compaction.go:73-113`) and `precheckToolArguments` (`agents-plugin-tool/internal/mcp/tool_arguments.go:55-65,84-155`) ALWAYS keep the canonical `compact` argument schema (including `lead_summary`) so the server unconditionally accepts both:
  - No-arg / summary-less calls (`{session_key, ...}` without `lead_summary`), and
  - Complete 7-field `wscompact.LeadSummary` (+ optional `reread`, `<= 12` paths) validated by `wscompact.ParseLeadSummary` (`agents-plugin-tool/internal/wscompact/summary.go:54-83`), rejecting partial structs or unknown fields (`additionalProperties: false`).
  - Note: because `precheckToolArguments` looks up schemas from the static `tools()` table (`mcp/tool_arguments.go:55-65`) rather than the per-session `filteredTools()` output (`mcp/server_inventory.go:74-118`), projecting `lead_summary` out only in `filteredTools()` preserves the single server acceptance contract cleanly without breaking precheck.
- **Conditional `tools/list` projection per session:** `Server.filteredTools()` (`agents-plugin-tool/internal/mcp/server_inventory.go:74-118`, served by `mcp/server.go:421-430`) projects the `compact` tool schema per session based on caller role and the resolved `compaction.lead_mode` knob for that session's harness (announced corollary of `(1537)=a` and `(1539)=a` lead-only Phase 1 scope):
  - **Hosted leads only (`s.conversation != ""`, `!s.workerForwards()`, and hosted-lead binding via `s.agents != nil` / `s.callerBinding`, matching `userCommandsListed()` in `server_inventory.go:84-88`):**
    - When effective `compaction.lead_mode` is **`native`** (off): strip `lead_summary` from the advertised `compact` `inputSchema` (lightweight no-arg view: `656 B` on `ws` / `660 B` on `wsflow` in Go `encoding/json`, saving `712 B`; `agents-plugin-tool/internal/mcp/compaction.go#L59-L67`, `agents-plugin-tool/internal/wscompact/summary.go#L35-L51`).
    - When effective `compaction.lead_mode` is **`ws`** (on, including `werk` durable leads): advertise the full structured 7-field `lead_summary` + `reread` schema (`1368 B` on `ws` / `1372 B` on `wsflow`, within `toolSchemaByteCap = 1450 B`; `agents-plugin-tool/internal/mcp/compaction.go#L59-L67`, `agents-plugin-tool/internal/wscompact/summary.go#L35-L51`, `agents-plugin-tool/internal/mcp/tool_schema_size_test.go#L18`). Update `wscompact.LeadSummarySchema()` description (`wscompact/summary.go:35-51`) from `"Builtin lead self-compaction prose..."` to harness-agnostic wording while keeping total serialized size well below `1450 B`.
  - **Workers (`s.workerForwards()`) and non-hosted / CLI launcher connections (`s.conversation == ""`):** ALWAYS strip `lead_summary` from `tools/list` even when `compaction.lead_mode=ws` is configured on that harness, because Phase 1 defers worker `lead_summary` forwarding (`(1539)=a`) and non-hosted sessions cannot run hosted compaction.
- **Mid-session knob toggle safety:** Toggling the compaction mode knob mid-session never breaks an in-flight session because the server always accepts both no-arg and `lead_summary` calls; the updated `tools/list` schema view takes effect on the next session start or MCP reconnect. No `/mcp` `ProxyHello` wire change is required because `mcp.Server` already has `ServerOptions.Harness` (`agents-plugin-tool/internal/mcp/process_env.go#L61-L63`), `ServerOptions.Conversation` (`agents-plugin-tool/internal/mcp/process_env.go#L111-L115`), and `s.sessionResolver(...)` (`agents-plugin-tool/internal/mcp/server_config.go#L72-L75`; search for `configResolver` in `agents-plugin-tool/internal/mcp/*.go` returned nothing).

### 2. Two-Stage Fallback on External Harnesses Triggered Without `lead_summary` (Owner-Confirmed `(1538)=a`, Refined `(119)=b`)

When a hosted external-harness lead (`claude`, `codex`, `agy`) has ws-managed compaction enabled and compaction is triggered **without** a `lead_summary`:
- **Automatic hard-threshold crossing** (`stageHardCompaction` / `steerCompaction`, `wsagent/compaction.go:546-630`), or
- **Dashboard `/compact` command** (`wsdashboard/inbox_routes.go:489` -> `wsagent/runner_conv.go:1979-2051` `kick()` intercepting `cmd.Name == "compact"` before direct `runCommand`)

execute the **two-stage fallback**:

1. **Stage 1 (1-shot `lead_summary` steer):** Reuse the existing hard compaction advisory steer/nudge mechanism (`wsagent/compaction.go:589-630,683-688`, updating the gate in `stageCompactionNudge` from `durableProcess(rec.Backend)` to effective ws-managed mode) to request a single bounded turn instructing the lead to save durable state to its agenda and call `ws/compact` with `lead_summary`. Because a session connected before a mid-session `native` -> `ws` toggle holds the stale no-arg `tools/list` schema until reconnect, the Stage 1 steer text explicitly lists all 7 required string fields (`user_preferences`, `working_practices`, `unrecorded_decisions`, `current_work`, `next_step`, `mood_rapport`, `residual_details`, using `""` when empty) plus optional `reread` (array of up to 12 worktree text file paths) rather than relying on the client's cached tool schema (technical detail under `(1538)=a`: inline field list in steer over relying on `tools/list` schema, ensuring mid-session toggles work without reconnect).
   - If the lead calls `ws/compact(lead_summary)` during that turn, the idle boundary executes the ws-managed checkpoint + native session rotation (Section 4) and clears the fallback state.
2. **Stage 2 (native `/compact` fallback):** If the Stage 1 turn finishes without queuing `ws/compact(lead_summary)` or errors/aborts, fall back to the harness's native `/compact` path (`c.runCommand(wsinbox.Command{Name: "compact"})`, `wsagent/compaction.go:455-462`) so context pressure is always relieved rather than looping or stranding the session. If the Stage 1 turn ends with `NoticeUsageLimit` (quota exhausted), suppress immediate Stage 2 native `/compact` firing so quota continuation can handle recovery without burning into an exhausted window.
3. **No-arg `ws/compact` MCP call (`(119)=b`):** To preserve argument-driven tool semantics, a direct `ws/compact` call **without** `lead_summary` from a `compaction.lead_mode=ws` external lead does **not** spend a Stage 1 steer turn; it falls back directly to the harness's native `/compact` path (`runCommand(wsinbox.Command{Name: "compact"})`). Passing `lead_summary` selects ws-managed checkpoint + session rotation; omitting `lead_summary` selects native `/compact`.

### 3. Phase 1 Scope and Opt-In Default (Owner-Confirmed `(1539)=a`)

- **In scope (Phase 1):** All hosted leads across `claude`, `codex`, `agy`, and `werk` unified under one ws-managed compaction engine, controlled by the harness-applicable core config key `compaction.lead_mode` (technical detail under `(1539)=a`: `compaction.lead_mode` over `compaction.mode`, matching the existing `compaction.<role>_<setting>` family `compaction.lead_advisory` / `compaction.lead_hard` / `compaction.worker_advisory` / `compaction.worker_hard` in `wsconfig/compaction.go:12-15` and keeping Phase 1's lead-only scope separate from deferred worker compaction mode; Rejected: `compaction.mode`). Values: `native` | `ws`, `HarnessApplicable: true`, `NoAgentVisible: true`, wired into `notifyCompactionTune` / `compactionConfigGen` (`mcp/compaction.go:14-42`).
- **Default posture & descriptor placement (opt-in for dogfooding, technical detail under `(1539)=a`):** Per-harness default lead mode and ws-only capability live on `BackendRegistration` (e.g., a runtime-only policy field on `BackendRegistration` / `LifecyclePolicy` in `wsagent/registration.go` / `wsagent/backend_policy.go` — NOT on `CompactionProtocol`, which `catalog.go:143` reserves for native lifecycle/prompt facts rather than policy and which `werk` does not populate) rather than harness-name branches in shared code (preserving `261117-feat-ws-hosted-compaction-lifecycle` and `261118-refactor-ws-harness-name-branches` descriptor rules). External harnesses (`claude`, `codex`, `agy`) declare default `native`; `werk` declares default `ws` and ws-only (no external native `/compact` command). `config.tune` rejects an explicit harness-targeted write `compaction.lead_mode.<harness>=native` for a ws-only descriptor (`werk`) with a validation error, while a wildcard `compaction.lead_mode=native` (or hand-edited config entry) normalizes to `ws` at runtime so wildcard defaults never break `werk` (Rejected: putting policy flags on `CompactionProtocol`, silently ignoring explicit `compaction.lead_mode.werk=native` writes, or failing at runtime on wildcard `* = native`).
- **Explicitly deferred out of Phase 1:**
  - Worker `lead_summary` forwarding across the child token-forward path (`agents-plugin-tool/internal/wsagent/children.go:298-308` currently forwards only `Target` and `Resume` and calls `r.Compact(...)`); workers stay on their existing compaction path in Phase 1.
  - Flipping the external-harness default from `native` to `ws` (follows after dogfooding validates real-world rotation quality across `claude`/`codex`/`agy`).

### 4. Context Reset Primitive: Native Session Rotation (Owner-Confirmed `(1551)=a`, `(1552)=b`)

Instead of sending harness-specific `/clear` commands or introducing a persisted multi-segment harness chain, ws-managed compaction on external hosted leads resets model context at the idle boundary via in-place **native session rotation** (retaining `261117-feat-ws-hosted-compaction-lifecycle` `(35)`'s single-ws-session rule; see Section 7):

1. **Quiescent checkpoint assembly & commit:** At the hosted idle boundary (`compactIdle`, `wsagent/compaction.go:417-538`), assemble the markdown checkpoint via the shared `internal/wscompact/` engine (carry-forward prose + bounded `reread` files from `wsdashboard.ReadWorktreeTextFiles` + recent `## Dialog` tail from the RAM-pinned `wslive` ring + active ticket/playbook refs + `r.compactionState(rec.ReplyID)` children/exec-job snapshot).
2. **Explicit audit checkpoint:** Record an explicit, non-estimated `wsaudit.KindCompaction` checkpoint via `auditCapture.commitCheckpoint` (`agents-plugin-tool/internal/wsagent/audit_capture.go#L285-L327`)—matching `werk_loop.go:244-261`—so all harnesses including `agy` emit explicit checkpoints instead of falling back to `audit_agy.go:258-300` estimated `usage_drop` inference.
3. **Rotate native session ID while preserving ws identity:**
   - Stop/retire the current harness process/holder cleanly (`retireHolder`, `wsagent/runner_lead_start.go:323-344`).
   - Clear only the harness-native session binding (`rec.SessionID = ""`, plus any harness-specific native session handle such as `rec.SessionFile` if applicable) while preserving all ws-owned session identity and history: `rec.ReplyID`, `rec.WSKey`, `ring/` (`wslive`), `wsaudit` segment log, children/mail bindings, worktree/cwd, and permissions.
   - Start a fresh native session via `startLead` (`wsagent/runner_lead_start.go:21-318`):
     - **`claude`:** omits `--resume` when `spec.SessionID == ""` (`wsagent/claude.go:184-186`).
     - **`codex`:** sends `thread/start` instead of `thread/resume` when `spec.SessionID == ""` (`wsagent/codex.go:255-264`).
     - **`agy`:** sends `session/new` instead of `session/resume` when `spec.SessionID == ""` (`wsagent/agy.go:451-458`).
     - **`werk`:** unchanged in-place transcript replacement `a.transcript = []json.RawMessage{userItem(checkpoint.Summary)}` (`werk/compaction.go:119-124`).
4. **Restore delivery & continuation:** Deliver the assembled checkpoint + `RestoreCompaction` session-state bundle into the fresh session's first turn (reusing `queueRestore` / `renderPendingNote`, `wsagent/compaction.go:882-933`, and `compactEvent` lifecycle accounting `CompactStart`/`CompactEnd`/`CompactFailed`, `cmpCount`, `cmpLast`, `wsagent/compaction.go:774-834`), starting one continuation turn when `resume` is true (default true for self-compaction).
5. **Failure safety:** If checkpoint assembly or rotation fails before the fresh session is established, emit `CompactFailed` without incrementing `cmpCount`, preserve the prior `rec.SessionID` (or leave recovery clean), and surface the error rather than silently dropping session state.

### 5. Shared Harness-Agnostic `internal/wscompact/` Engine

Lift the shared checkpoint assembly primitives out of `internal/werk/` into `internal/wscompact/` so `werk` and `wsagent` call one implementation with zero duplicated formatting logic:

- Move from `agents-plugin-tool/internal/werk/compaction.go:18-26,186-343` and `agents-plugin-tool/internal/werk/lead_compaction.go:10-72` into `agents-plugin-tool/internal/wscompact/`:
  - `CompactionState` (`ChildrenInFlight`, `ChildrenFinished`, `ExecJobs`) — unifying the duplicate struct currently defined as exported `CompactionState` in `agents-plugin-tool/internal/werk/compaction.go#L22-L26` and unexported `compactionState` in `agents-plugin-tool/internal/wsagent/compaction_snapshot.go#L11-L15`.
  - `reread` smallest-first bin-packing under `RereadBytes = 40 << 10`, `<file path=...>` inlining with `</file>` escaping, and deferred file listing (`werk/lead_compaction.go:10-72`).
  - Ticket/playbook reference extraction (`ticketRefRE`, `skillRE`), bounded `## Dialog` tail assembly (`DialogBytes = 40 << 10`), section writer (`writeCompactSection`), and deterministic markdown checkpoint renderer (`summary` / `BuildCheckpoint`).
- Provide two dialog-source adapters feeding the shared renderer, explicitly accounting for their fidelity difference (technical detail under `(1539)=a`: zero-extra-file-I/O UI ring adapter over adding raw external-harness transcript storage):
  - `werk` continues feeding full-fidelity dialog from its transcript segment replay (`werk/compaction.go:62-97`).
  - `wsagent` (for external harnesses) feeds a best-effort dialog tail from the RAM-pinned `wslive` UI ring (`wslive.ReadRing` / `wslive.ReadRingPage`, `internal/wslive/ring.go:22-110,192-215`), relying on the lead's 7-field `lead_summary` and `reread` files for high-signal detail:
    - **Window:** collect entries chronologically after the newest successful `RingCompact` (`!CompactFailed`) boundary (or from ring start if none), then tail-truncate to `DialogBytes = 40 KiB`.
    - **Per-kind rendering:** `RingUser` and `RingReply` render `Text` (appending `[truncated]` when `Truncated` is true); `RingTools` renders a compact one-line summary from `Tools` (`ToolSummary` tool names/counts, acknowledging that raw tool payloads are already folded in the ring); `RingMail` renders a compact line with `Direction`, `Peer`, and `Title` (without opening separate mailbox-history files, preserving the zero-extra-disk-read budget); `RingWake` renders a compact marker (`Cause`/`Source`/`Caption`) when present; `RingCommand` renders `Command` and non-empty `Text`; non-dialog UI/lifecycle rows (`RingTurn`, `RingCard`, `RingUI`, `RingWhiteboardEffects`, failed `RingCompact`) are omitted.
