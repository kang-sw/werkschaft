# Composer bang command history popup and fuzzy search

## Background

The owner requested on 2026-11-23 at 13:25–13:26 KST, paraphrased from Korean:

> When I run commands with `!`, show my previous commands in a popup. Fuzzy-match recent commands as I type, like Ctrl+R. Keep the recent list in browser-local storage and let me delete entries with an ×. Use Up/Down to navigate and Tab to complete the selected command into the input.

This feature adds recall to the existing composer bang mode. The related terminal ticket covers the run output.

## Decisions

- **(1461) Approved mockup.** The empty `!` prompt shows history newest-first with command text, exit-code chip when known, relative time and a per-row ×. A fuzzy query ranks matches by score, breaks ties by recency, highlights matched characters in amber, shows `N / M 일치`, and preselects the top match. Ctrl+R advances to the next match. The third state shows a no-match query and an armed clear-all confirmation. [Approved mockup](../../assets/mockups/261123/composer-bang-history/history.html)
- **Keyboard navigation (owner, 13:26).** Up/Down navigate rows. Tab fills the input with the selected command.
- **(1462)=b.** Enter on a selected row fills the input and closes the popup. In the default send mode, a second Enter runs the filled command. See (1476) for the alternate mode. Rejected alternative was immediate execution on the first Enter.
- **(1463)=a.** Scope history by worktree. Rejected alternative was one browser-wide list.
- **(1464)=a.** Keep up to 200 entries per worktree. Repeating a command moves its single entry to the top. Drop the oldest entries over the cap. Cap each stored entry at 2 KB. Rejected capacities were 50 and 500 entries.
- **(1465)=a.** Include `전체 지우기` with a two-step confirmation. The armed state expires after three seconds as shown in the mockup. Rejected alternative was per-row × only.
- **(1466)=a.** Open the popup automatically when `!` is typed and history exists. The first Esc closes the popup and the second Esc uses the existing bang-mode exit behavior. Rejected alternative was opening only on Up or Ctrl+R.
- **(1467)=a.** Show relative time and an exit-code chip. Record the exit code when the run ends and omit the chip when the code is unknown. Rejected alternative was command text only.
- **(1468), technically acknowledged.** Hide the popup when the worktree has no history. On a query with no matches, the configured send action runs the typed command as-is.
- **Storage and compatibility.** Use browser `localStorage` as requested by the owner. The new key and its data are client-only and the Go routes and payloads stay as they are. Compatibility is T0 because previous binaries never read or overwrite the new key.
- **(1476)=a.** Once the input is filled, or when the query has no matches, use the configured send action to execute. The default Enter mode follows the approved mockup. Render the hint for the active send chord. See (1486) for how Enter and the send chord handle an active selection.
- **(1477), acknowledged.** Record positively identified composer bang runs once per submission ID, including retries. A refusal or unknown attempt creates no history row. A retry that establishes a known run records it once. Use the distinctions in `cexecSend`, `composerRun` and commit `ce20146ad`.
- **(1478)=a (updated by (1503) for `(1493)=a`).** Keep bounded exit-status tracking for a pending history row even after the user dismisses or clears its UI status entry (formerly console card; now `.xchip` dismiss/fade in `.xgroup` / `xpeek` per `(1493)=a` and `(1503)`). Removing or clearing history stops tracking the affected rows.
- **(1479), acknowledged.** Bind history to the current worktree tag provided by the existing user-command list and revision wake (`rootTag`, `List` and `Revision` in `agents-plugin-tool/cmd/ws-mcp/usercmd.go#L63-L120`). The tag is a 32-bit hash with a nonzero collision risk. History stays unavailable until the binding is known, and users can still run commands. Rejected: the standalone `data-worktree` attribute is absent on composer pages (`agents-plugin-tool/internal/wsdashboard/assets/dashboard.tmpl#L2,L19-L26`), reply IDs would split one worktree's history by session, and a shared fallback would mix worktrees.
- **(1480)=a.** Apply history deletion and stale-completion guarantees across same-origin pages for the same worktree. A completion in one page cannot restore a row another page removed or cleared, or overwrite a newer run of the same command.
- **(1486)=a.** With a history row selected, plain Enter and the configured Ctrl+Enter or Cmd+Enter send chord both fill the selected command and close the popup. A subsequent send executes the filled command. This gives both keys the same selection behavior and preserves the separate execution action. Enforce a separate-press guarantee against held-key `KeyboardEvent.repeat` in `capsules.js` / composer keyboard forwarding (`agents-plugin-tool/internal/wsdashboard/assets/capsules.js#L274` currently constructs the forwarded `KeyboardEvent` without `repeat: e.repeat`, and `dashboard-composer-keyboard.js` has no `.repeat` check; empty search for `\.repeat\b` across `agents-plugin-tool/internal/wsdashboard/`) so holding Enter or Ctrl/Cmd+Enter cannot execute immediately after closing the popup.
- **(1494)=a (owner confirmed 2026-11-23).** Add a compact 24px-tall "실행 이력" (`Command history`) badge in the out-of-flow `.cbadges` strip directly beside `.xgroup` (same 24px height as `.xchip`, zero vertical composer height growth). Clicking the badge opens or toggles the same `!` history popup (working even when the composer input does not yet start with `!`; picking a row fills `!<cmd>` and closes the popup), while keeping the automatic popup when `!` is typed (`(1466)=a`). Rejected: `(b)` removing `!` auto-popup; `(c)` making the badge a separate `xpeek`-style output viewer.
- **(1493)=a alignment (owner confirmed 2026-11-23).** Because `261123-feat-ws-composer-bang-terminal-look` Phase 4 removes the in-flow `.d-cexec` console (pending 261123-feat-ws-composer-bang-terminal-look), history recording and pending exit-code tracking do not depend on `.d-cexec` console cards; they read admission results (`submission_id` from `cexecSend` and `exec_id` from the Phase 4 `ws:cexec-admitted` `CustomEvent` emitted by headless `cexecPoll` and immediate `POST 200` retry responses for `origin === "cexec"` per `(1501)`/`(1502)`/`(1505)`, `agents-plugin-tool/internal/wsdashboard/composer_exec.go#L531-L548,#L736-L763,#L1055-L1068`) and monitor job origin and exit status through the existing `.xgroup` Exec HUD (`/s/<rid>/exec/jobs`) list and refresh path.
- **(1502) [technical, confirmed 2026-11-23].** Consume the headless `cexecPoll` / immediate `POST 200` retry admission hook (`ws:cexec-admitted` `CustomEvent`, filtering to `origin === "cexec"` and ignoring `origin === "ucmd"` registered slot clicks per `(1505)`) from `261123-feat-ws-composer-bang-terminal-look` Phase 4 (`(1501)`) over modifying Go `/s/<rid>/exec/jobs` (`execJobView`) to add `submission_id`. `POST /s/<rid>/composer-exec` returns `202` with `submission_id` before `composerRun` assigns `exec_id`, and `execJobView` (`agents-plugin-tool/internal/wsdashboard/exec_hud.go#L56-L71`) does not carry `submission_id`; consuming Phase 4's `ws:cexec-admitted` event preserves the client-only T0 boundary while cleanly pairing `(submission_id, command)` with `exec_id` for `/s/<rid>/exec/jobs` worktree-origin verification and exit-code tracking. Rejected: adding `submission_id` to Go `execJobView` (breaks client-only T0 scope); relying on removed `.d-cexec` console cards.
- **(1503) [announced, confirmed 2026-11-23].** Supersede `(1478)=a`'s legacy `.d-cexec` console-card dismissal wording to match `(1493)=a`: keep bounded exit-status tracking via `/s/<rid>/exec/jobs` for a pending history row even if the user dismisses or fades the job's `.xchip` in `.xgroup` / `xpeek`; removing or clearing the history row stops tracking it. Direct consequence of `(1493)=a` removing `.d-cexec` console cards.
- **(1506) [technical, auto-confirmed from Sage design & completeness review 2026-11-23].** Hide the `.cbadges` "실행 이력" badge (`hidden = true`) whenever the current worktree has no history or while the worktree binding is not yet known (matching `(1468)` and `.cbadges`'s `#bgbadge`/`#monbadge`/`.xgroup` convention so no inert button consumes `.cbadges` chip width), include the badge in `xhLayoutNow` and `xhRo` (`dashboard-exec-hud.js#L183,#L313`) so `.xgroup` never collides or overflows, and when opened via the badge while the composer does not start with `"!"`, treat the filter query as empty (newest-first, no separate search input), close on non-`"!"` typing, and replace the field with undoable `editText("!<cmd>")` on row selection per `(1494)=a`. Rejected: showing an inert empty-history badge (wastes `.cbadges` width and conflicts with `(1468)`); adding a second search input inside `.chist`.

Apply mutations to the shared worktree history so a page's stale view cannot restore a deleted row, undo a clear, or overwrite metadata from a newer run of the same command. Keep over-limit commands runnable and skip persistence if an entry exceeds 2 KB when serialized in UTF-8, so recalling a command always restores its full text.
