# Dashboard Main Board: Remove Snap-Deck and Switch to Designated-Y Free-Canvas Virtual Scroll

## Background

`main-panel-snap-deck` (`261123-feat-ws-dashboard-main-panel-snap-deck`, Phases 1–4, shipped in `v0.51.2`; `ai-docs/tickets/.done/261123-feat-ws-dashboard-main-panel-snap-deck.md`, commit `34c85dfc4`) eliminated the dashboard's severe main-board frontend lag, which was driven primarily by uncached visibility scans, full-board DOM layout/exposure work during SSE `morphBoard`, and mounting every card's heavy body/iframe at once. However, the snap-deck interaction itself — stretching short cards into 100%-viewport fixed slots (`--board-slot-h`), trapping tall cards inside nested inner scroll boxes, and intercepting every wheel event through `WsBoardWheel` — feels rigid and clunky compared to free vertical scrolling of variable-height cards.

The owner confirmed (`(1518)=a`, `(1519)`, `(1526)=a`) that we should replace snap-deck with a **Designated-Y (anchor-relative free-canvas) windowed variable-height virtual scroll** in `#bcol`, keeping variable card heights, native browser scroll momentum, the right-side index-based dot scrollbar (`#bdial`), and the frontend performance gains achieved by snap-deck.

## Decisions

1. **Variable-height free scroll over fixed-slot snap-deck (`(1518)=a`).** Remove snap-deck's fixed viewport-height slot sizing (`--board-slot-h`), inner card scroll traps, and JS `wheel` interception (`WsBoardWheel` / `anchorGlide`). Keep `#bcol`'s hidden native scrollbar (`scrollbar-width: none` / `::-webkit-scrollbar { display: none }`) and keep the right-side index-based dot scrollbar (`#bdial`) as the canonical navigation rail.
   - *Rejected:* Tuning snap-deck wheel thresholds or keeping fixed 1-card-per-viewport slots (does not restore free variable-height stacking/scrolling feel).
   - *Rejected:* Exact total `scrollHeight` accounting across all cards (unnecessary because `#bcol` hides its native scrollbar and `#bdial` is purely index-based).
2. **Designated-Y anchor-relative free-canvas positioning (`(1519)`).** Render only an active window of cards around the current anchor card (baseline `±3` cards, expanding up to `±8` cards as needed to cover at least `1.5×` viewport height above and below) using `position: absolute; top: Ypx; left: 0; right: 0` inside `#r-board`. Cards below the anchor lay out downward (`y_i = y_{i-1} + h_{i-1} + gap`); cards above the anchor lay out **upward** (`y_i = y_{i+1} - gap - h_i`).
   - *Rejected:* Normal-flow top-down stacking (requires stashing above-viewport buffer updates or fighting browser scroll anchoring with reactive `scrollTop` jumps whenever an above-viewport card resizes).
   - *Rejected:* `transform: translateY(...)` positioning (creates a CSS containing block that traps `position: fixed` descendants such as `[data-max]` maximized sheets and `.dw .pop` dependency popovers, breaks sticky headers on the stage, and introduces subpixel blur under Windows DPI scaling).
3. **Native `#bcol` scroll + Bounded Runway idle recentering (`(1526)=a`).** Preserve genuine browser native scrolling on `#bcol` (wheel, trackpad inertia, touch, keyboard, `.tophead` / `.bc-hd` `position: sticky`) over a bounded runway with default height `RUNWAY_HEIGHT = 2 * RUNWAY_MID = 100000`px (`rBoard.style.minHeight = stageH + "px"`, `stageH = RUNWAY_HEIGHT` whenever Card `N-1` is not in the window) centered at `RUNWAY_MID = 50000`px. When scrolling goes idle (`150ms` debounce, not scrubbing), the mounted window is NOT boundary-clamped (`winStart > 0` and `winEnd < N - 1`), and the mounted window approaches a runway margin (`y_first < 10000` or `y_last > stageH - 10000`), synchronously rebase all mounted `y_i` and `col.scrollTop` by `delta = RUNWAY_MID - y_anchor` in the same frame (`0px` visual shift).
   - *Boundary clamping:* When Card `0` enters the window (`winStart === 0`), synchronously shift mounted `y_i` and `col.scrollTop` so `y_0 = topPad` (immediately below `.board-toolbar`), so `scrollTop = 0` is the exact top of Card `0` (and skip idle recentering while `winStart === 0`, even though `y_0 = topPad < 10000`). When Card `N-1` enters the window (`winEnd === N - 1`), place `button.closed-more` (if present) at `y_{N-1} + h_{N-1} + gap` and set `rBoard.style.minHeight = Math.ceil(lastBottom + botPad) + "px"`, so native scroll stops cleanly at the last card (and skip idle recentering while `winEnd === N - 1`).
   - *Jump centering (`#bdial`, Overview exit, keyboard/deep-link jump):* `WsBoardAnchor.select(card, { smooth: false })` must synchronously un-hide (`data-wb-offwindow`), hydrate via `WsBoardVirtual`, and position `card` before returning so 2-level jump callers (`wbHistory.navigate`, `card-find.js#L361,L372`, `focusTopicNote`) can immediately measure and scroll inside `card`. Place `targetIdx` at `RUNWAY_MID` (or anchored to `topPad` when Card `0` is in the window), hydrate `[target - before .. target + after]`, and jump `col.scrollTop` so short/medium target cards land centered in the viewport and tall cards (`h >= viewportH`) land top-aligned below sticky headers.
   - *Rejected:* Pure JS `wheel`-virtualized `Y = 0` viewport canvas (breaks native trackpad momentum, touch fling, and `position: sticky` headers); leaving `stageH` unspecified or recentering while boundary-clamped at `winStart === 0` / `winEnd === N - 1` (`(01)`).
4. **Viewport-only update guard + unblocked buffer updates (`(1519)`).** Guard live SSE/`morphBoard` visual updates ONLY for cards currently intersecting the visible viewport (plus any active editor), so text the user is actively reading never shifts under their eyes. Update `anchorExposed()` (`dashboard-board-anchor.js#L1080-L1098`) in free-canvas mode to check whether the target card intersects `#bcol`'s visible viewport rather than hard-coding `anchorCurrent()` only, and flush held updates via `boardFlushViewed(false)` whenever scroll settles / a held card exits the visible viewport (and on `focusout` for an active editor). Above-viewport and below-viewport mounted buffer cards update immediately: with `anchor` as the topmost viewport-intersecting card, a single shared `ResizeObserver` on the mounted window shifts `y_j -= dh` for `j <= k` when `k < anchor` (growing upward from `y_anchor`) and `y_j += dh` for `j > k` when `k >= anchor` (growing downward below `k`), yielding `0px` shift on the anchor and all visible cards.
   - *Rejected:* Keeping single-card `anchorCurrent()` exposure in `anchorExposed()` or omitting native-scroll flush (leaves non-anchor visible cards unguarded and held updates stuck after scroll-out, `(03)`); shifting all `y_i` on `k < anchor` / `k >= anchor` instead of exact `j <= k` / `j > k` ranges (`(07)`).
5. **Compatibility tier: `T0` (transparent).** Pure frontend CSS/JS asset change inside `agents-plugin-tool/internal/wsdashboard/assets/` and `agents-plugin-tool/internal/wswhiteboard/assets/`. No MCP tool schema, wire protocol, `/mcp` hello, config manifest, or on-disk store format changes.
6. **Cross-module free-canvas coordination (`(02)`, `(04)`, `(05)`, `(06)`, `(07)`).**
   - `pill.js` & narrow-mode `gateWheelInput`: Classify open-question items inside `[data-wb-offwindow]` topics via `WsBoardAnchor` window index (`< winStart` -> above, `> winEnd` -> below, skipping folded/unrendered items) instead of dropping `0x0` rects (`pill.js#L397-L408`), and treat `last.hasAttribute("data-wb-offwindow")` as `can = true` in `cards.js#L1229-L1236` so narrow-mode Page 0 -> Page 1 flips never fire while Card `N-1` is off-window. *Rejected:* Letting `0x0` off-window rects drop `.oq-pill` counters and trigger premature gallery flips (`(02)`).
   - Overview entry & exit: On Overview entry (`overview.js#L386-L423`) and in `:root[data-overview]` / `.overview-preview-stage`, strip or override inline `style.top` and `#r-board` `style.minHeight`, and bypass FLIP `snapshot()`/`motion()` in `enter()` under free-canvas (matching `exit()`'s `fastSnap` path at `overview.js#L460`). *Rejected:* CSS-only `:root:not([data-overview])` scoping that leaves `top: 50000px` / `minHeight: 100000px` shifting cards off-screen (`(04)`).
   - `boardKeep` / `wbHistory.keep` scope: Keep scroll-anchor compensation active for the anchor card (`k === anchor`) inside `#bcol[data-board-free]` (and for `#bgal`) so late frame growth or history prepends above the reading line inside a tall current card do not jump the viewport, while skipping compensation for above-anchor buffer cards (`k < anchor`) across `boardKeep` and other `wbHistory.keep` callers (`dashboard-frames.js#L209,L501`, `stream.js`, `stream-navigation.js`) where `ResizeObserver` already shifts `y_j` upward. *Rejected:* Unconditionally skipping `boardKeep` for all `#bcol[data-board-free]` frames (`(05)`).
   - `loadClosed()` settlement: Call `WsBoardAnchor.settle()` (and `boardDialSync()`) after inserting `.closed-page` in `dashboard-conversation.js#L611-L649` so newly loaded closed topics are positioned immediately rather than stacking at `top: 0`. *Rejected:* Settling only in `morphBoard` / `swap("board", ...)` (`(06)`).
   - `rail.js` indexing & ghost stability, `.bc-body` height, `VIRTUAL_KEEP_ATTRS`: Propagate `offBefore`/`offAfter` from `anchorCache` across `k`/`above`/`up`/`down`/`upMore`/`downMore` in `rail.js#L152-L197` and avoid `dropGhost()` on free-canvas `#r-board` `minHeight` mutations (`rail.js#L489,L499`); remove `height: auto !important` on `.bc-body` (`dashboard-board.css#L403`) alongside `--board-slot-h` so `terminal`/`web` `.bcard` bodies do not collapse to `0px`; add `data-wb-offwindow` to `VIRTUAL_KEEP_ATTRS` (`dashboard-board-anchor.js#L149-L154`). *Rejected:* Leaving `rail.js` ghost drops, `.bc-body` collapse, or `VIRTUAL_KEEP_ATTRS` unaddressed (`(07)`).
7. **Split off-window hiding for ordinary vs `virtualIsItemExempt` cards (`(08)`).** Preserve `261123-feat-ws-dashboard-main-panel-snap-deck` Phases 3–4 live-preservation (`virtualIsItemExempt` in `dashboard-board-anchor.js#L156-L159,L219-L237`):
   - Ordinary non-exempt off-window topics receive `data-wb-offwindow="hidden"` (`display: none` + `WsBoardVirtual` body eviction).
   - Exempt off-window cards (unpinned `.bcard` widgets `terminal`/`web`/`preview`/`explorer` and active-edit/focused/selected/terminal topics) receive `data-wb-offwindow="parked"` plus HTML `inert` (`left: -200vw; right: auto; width: 100%; top: 0 !important; visibility: hidden; pointer-events: none;` under `:root:not([data-overview]) #bcol[data-board-free]`, never matching `[data-max]`, never `display: none`) and are unobserved by the free-canvas `ResizeObserver` while off-window; `data-wb-offwindow` and `inert` are stripped on window re-entry, Overview entry, `#bgal` dock, or `[data-max]` maximize.
   - *Rejected:* Applying `display: none` uniformly to all off-window cards (reverses Phases 3–4 live preservation for unpinned `.bcard` widgets and active-edit topics); leaving exempt off-window cards unparked in `position: absolute` (causes visual collisions on `#r-board`).
