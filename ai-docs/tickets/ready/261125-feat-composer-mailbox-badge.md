# Composer Mailbox ID (`<mailbox/>`) Paste Badge Rendering

## Background

Copying a session's mailbox reference from the dashboard header (`.snm`), session rail (`.drcopy`), or rail context popover puts an XML tag onto the clipboard in one of two forms generated by `SessionView.MailboxRef` (`pageview.go`) and `labelCopy` (`dashboard-actions.js`):

- Self-closing (empty label): `<mailbox id="id:..." dir="..." [root="..."] [branch="..."] [harness="..."]/>`
- With label: `<mailbox id="id:..." dir="..." [root="..."] [branch="..."] [harness="..."]>escaped-label</mailbox>`

Pasting that clipboard string into the composer currently inserts the raw XML text verbatim via `insertPlain()` (`capsules.js`), cluttering the prompt. The composer should recognize pasted `<mailbox .../>` / `<mailbox ...>...</mailbox>` tags and render them as structured badges while preserving the canonical `<mailbox ...>` wire text on send.

## Decisions

- **Recognize `<mailbox>` tags on paste in the composer:** Pasting `<mailbox .../>` or `<mailbox ...>...</mailbox>` into the dashboard composer renders it as an inline `WsCapsules` `mailbox` badge instead of raw XML text.
  - Rationale: Matches existing `WsCapsules` inline badges (`skill`, `topic`, `mention`, `ticket`, `pick`, `console`, `panel`, `selection`) and keeps prompts legible when referencing peer sessions.
  - Rejected: Leaving raw XML inline in the composer text area.
- **Hydrate `<mailbox>` badges in both composer and `#convo` (`(1610)=a`, T0):** Render `<mailbox>` tags as badges in the composer (`capsules.js`) **and** in `#convo` held/delivered user bubbles (`pageview_inbox.go` + `dashboard-composer-delivery.js`), keeping the wire text verbatim `<mailbox .../>` / `<mailbox ...>label</mailbox>` (strictly **T0**).
  - Rationale: Keeps pre-send and post-send visual presentation consistent without changing any wire format or agent-visible text.
  - Rejected: Composer-only badge rendering (would flash raw escaped XML in `#convo` after send).
- **Context-aware dynamic badge label & raw-paste bypass (`(1611)=a`):** Compute the badge label dynamically relative to the current viewing session's `dir` and `branch`:
  - Different `dir`: `<dir-name>:<branch>` (plus session label when non-empty).
  - Same `dir`, different `branch`: `<branch>` (plus session label when non-empty).
  - Same `dir` and same `branch`: session `label` only (fallback to short `id:` when unlabeled / self-closing).
  - Hover tooltip exposes full `id`, `dir`, `root`, `branch`, and `harness` metadata.
  - `Ctrl+Shift+V` (or `Cmd+Shift+V`) bypasses badge conversion and pastes raw XML text verbatim (consistent with `261125-feat-composer-long-paste-textref`).
  - Rationale: Surfaces the differentiating context (`dir` / `branch`) first while still showing the session label when present, and provides an escape hatch when raw XML is needed.
  - Rejected: Hiding the session label whenever `dir` or `branch` differs (`(1611)` option b).

## Constraints

- **Required manuals:** `ai-docs/manuals/performance.md` (`## Frontend Minimal Updates`), `ai-docs/manuals/dashboard-style.md`, `ai-docs/manuals/release-compatibility.md`, `ai-docs/manuals/shipped-surface-boundary.md`.
- Convention: ai-docs/manuals/shipped-surface-boundary.md (declared for agents-plugin/, agents-plugin-wsflow/, agents-plugin-tool/)
- Convention: ai-docs/manuals/release-compatibility.md (declared for agents-plugin-tool/internal/)

- Convention: ai-docs/manuals/dashboard-style.md (declared for agents-plugin-tool/internal/wsdashboard/assets/, agents-plugin-tool/internal/wswhiteboard/assets/, ai-docs/assets/mockups/)
- **Compatibility tier:** T0 (`(1610)=a`) — the underlying `#ctext.value` and `<ws:user>` wire text remain the exact `<mailbox .../>` or `<mailbox ...>...</mailbox>` XML so agents and older daemons/clients continue working unchanged.
- **Schema fidelity:** Support both self-closing `<mailbox .../>` and non-empty `<mailbox ...>label</mailbox>`, with XML-escaped attributes (`&`, `<`, `>`, `"`) and escaped inner text (`&`, `<`, `>`), and safely ignore malformed or partial tags.
- **Draft & copy round-trip:** `WsCapsules` copy/cut/undo and `readDraft`/`restoreDraft` (`dashboard-lifecycle.js`) must preserve the exact backing `<mailbox ...>` range in `#ctext.value`.
- **CSS guard:** Do not introduce forbidden `:has()` selectors (`frontend-idle.test.js`).
- **Precedence with `<textref>`:** `<textref>` bodies (`261125-feat-composer-long-paste-textref`) are opaque. Mailbox scanning never runs inside a `<textref>` body in `#convo` hydration (server `hydrateProse` and client `hydrateProseInto`), and a composer paste of `>= 1024` chars that collapses to `[Text #N]` is not subject to mailbox badge conversion; textref extraction runs first.
- **Text-driven hydration path:** `inlineHydrator.hydrateProse` returns early when `!h.hasCandidates()` and its matchers bind to structured `Entry` data; a mailbox tag has no structured counterpart, so add a text-scanning branch that does not depend on candidates (and the same in `hydrateProseInto`).
- **Viewing-session context and label format:** The badge label uses the viewing session's `dir` (`SessionView.Project`, a full path) and `branch`; `dir` equality compares full paths, while the displayed dir-name is its basename. A session with no `branch` (plain folder, per `261113-feat-ws-dashboard-session-rail-tree`) shows the dir-name alone when `dir` differs. JS and Go must share one label-composition format for the "plus session label" combination, pinned by tests on both sides. The Go side sources `dir`/`branch` from the viewing session's view data passed into `hydrateUserMessage`; the composer JS reads the current session's `dir`/`branch` from the page.
- **Shared raw-bypass flag:** The `Ctrl+Shift+V` / `Cmd+Shift+V` flag has a single owner in `capsules.js` (set on `keydown`, cleared on `keyup` and when consumed by a `paste`), exposed as one readable accessor used by both the capsule `insertPlain` path and the textref `paste` listener; the later merger reconciles any duplicate found by the merge-tree check. Whichever of this ticket and `261125-feat-composer-long-paste-textref` lands second reuses the first's flag instead of adding a second tracker.

## Phases

### Phase 1: Composer `mailbox` Capsule Parsing, Dynamic Badge Rendering, and `#convo` Hydration

- Add a strict `<mailbox .../>` / `<mailbox ...>...</mailbox>` parser (handling attribute/text unescaping, multiple tags mixed with prose, and safe fallback on malformed XML).
- Register a `mailbox` capsule kind in `WsCapsules` (`capsules.js`, `dashboard-conversation.css`) so pasting mailbox references converts recognized tags into inline badges backed by the original XML text in `#ctext.value`, computing the dynamic label relative to the current session's `dir`/`branch` per `(1611)=a` and honoring `Ctrl+Shift+V` raw XML bypass.
- Add matching `<mailbox>` badge hydration in `pageview_inbox.go` and `dashboard-composer-delivery.js` for held and delivered `#convo` user bubbles (`(1610)=a`), using the viewing session's `dir`/`branch` context.
- Verify with local `node --test` tests (self-closing, labeled, escaped chars, same/diff `dir`/`branch` dynamic rendering, `Ctrl+Shift+V` bypass, mixed prose + multiple tags, malformed tag passthrough, draft save/restore, CSS `:has()` guard) and remote `w5090` `go test -race ./internal/wsdashboard`.
