# App-Scoped Shell Overlay, Left-Rail-Bottom Home Anchor, v3.1 Canvas Compositor & Active-View Relay

## Background

Werkschaft's dashboard already runs as a persistent same-origin iframe shell (`assets/dashboard.tmpl`, `assets/shell.js`, `assets/dashboard-lifecycle.js`) where normal session switches swap the inner iframe without reloading the outer shell. Mounting the companion once at the outer-shell level makes it genuinely **app-scoped** — smoothly accompanying the user across sessions while subscribing to a lightweight slice of whatever view/session is currently open.

Because main session panes are information-dense, the companion's default home anchor sits cleanly at the **bottom of the left session rail** (resting on the divider bar above `.rws-unreg` / `.rfoot`), scaling neatly to rail width while remaining freely draggable onto viewport landmarks (`composer-top`, `whiteboard-ask`, `hud-roster`).

## Decisions

- **App-scoped persistent shell mount (zero overhead when `off`):**
  - Mount the stage container (`position: fixed; inset: 0; pointer-events: none;`, with only the character hitbox and quick popover `pointer-events: auto`) once in the persistent outer shell (`dashboard.tmpl` / `shell.js`), never duplicated per session iframe.
  - When `window.wsCompanionConfig.mode === "off"`, keep the controller inert: zero pack fetches, zero `<canvas>` DOM/memory allocation, zero `requestAnimationFrame` loop, and zero iframe relay observers/timers. Toggling `off <-> visual/full` mounts/tears down cleanly via the live settings broadcast from `261122-feat-ws-companion-config-settings` (`agents-plugin-tool/internal/wsdashboard/companion_config.go#L34-L40`, `agents-plugin-tool/internal/wsdashboard/assets/dashboard-stream.js#L410-L416`).
  - When `mode !== "off"` and `document.hidden` is true (or minimized), pause the `rAF` loop and landmark polling (zero active frame work) while retaining the loaded in-memory pack/stage state for instant resume on visibility restore.
- **Default home anchor = left session rail bottom (with collapsed-rail fallback):**
  - Compute the `rail-home` anchor rect dynamically from the outer shell's left session rail footer divider (the top border of `.rws-unreg` when visible, falling back to `.rfoot` / `.r-config-global` in `dashboard.tmpl`), responsive to rail collapse/resize (`ResizeObserver`, `transitionend`, and viewport resize).
  - **Collapsed/offscreen rail (`< 1600 px` drawer closed, `dashboard-rail.css:37-41`):** Whenever `.rail` is collapsed/hidden (`visibility: hidden` or `rect.right <= 0` below `1600 px` without `.rail-open`), `rail-home` falls back to the **bottom-left viewport safe corner** (`left: 12 px`, `bottom: 12 px`, compact `~96 px` display size) so laptop viewports keep the companion visible and accessible. Opening the drawer (`.rail-open`) or widening to docked mode (`>= 1600 px`) smoothly transitions `rail-home` back to the visible rail footer divider (while respecting a user-dragged custom stage position until `Return home` is triggered). `Return home` always moves to the currently active `rail-home` target (rail divider when rail is visible, bottom-left viewport corner when rail is collapsed).
  - Scale default display size automatically to fit rail width (`~96–136 px`), keeping zero overlap with session rows or footer links.
  - Support pointer drag-and-drop (`dangle` pose + `prop-grab` behind head + drag-velocity pendulum swing) onto any reported landmark or viewport edge, with double-click or compact context menu returning home to `rail-home`.
  - Quick menu actions: `Return home` and `Hide/Mute` work on all viewers (local and remote); `Reload packs` (`POST /api/companion/packs/reload`, local same-origin `TrustedWrite`) and persisted preset edits are shown/enabled only when the shell has local write capability (`document.documentElement.hasAttribute("data-sysopen")` / local session). If a reload request is denied by either landed server path in `companion_pack_routes.go:140-148` (`404 Not Found` for non-local callers or `403 Forbidden` for failed same-origin checks), handle both gracefully with a localized non-fatal notice without disrupting the active pack, and keep preset switching session-local on read-only remote viewers.
- **Revision-Consistent Pack Loader & `auto` Resolution (`companion_pack_routes.go`):**
  - Fetch `GET /api/companion/packs[?harness=<h>&model=<m>]` (including the visible session's `harness`/`model` only when `window.wsCompanionConfig.pack === "auto"` on a session route; omitting them on sessionless routes or non-`auto` packs), bind the resolved pack `id` and `rev` to a monotonic `loadGen` counter, and fetch `GET /api/companion/packs/{id}/pack.json?rev={rev}` plus each flat raster via `GET /api/companion/packs/{id}/assets/{file}?rev={rev}`.
  - On `409 Conflict` (`X-Companion-Current-Rev`) or `404 Not Found` (reload race or removed resource), abort the current `loadGen`, discard partial layers, and restart from the catalog request (up to 2 retries before falling back to `"default"`). Always discard out-of-order responses whose `loadGen` is superseded by a session switch, config change, or reload, and swap the decoded bitmap set into the compositor atomically so layers from two revisions never mix.
- **Data-Driven `ws-companion/v1` Doll-Maker Canvas Compositor (`companion-pet-rigging.md`):**
  - Implement the v3.1 Canvas compositor from the canonical spec (`ai-docs/manuals/companion-pet-rigging.md`) and landed pack schema (`companion_pack_schema.go`) in modular asset fragments (`assets/dashboard-companion-compositor.js`, `assets/dashboard-companion-stage.js`, `assets/dashboard-companion.css`, registered in `pages.go` and `asset_source_test.go`, keeping module size clean and bounded):
    - `512 × 512` logical offscreen-cached compositor rendered at `devicePixelRatio` crispness down to `72 px`, implementing `ws-companion/v1` smart defaults (inferred layer mode, `z: 20`, `fallback: "stand"`, `headScale: 1.0`).
    - Canonical `head-egg` (`z30`) + open `expressions` dictionary (`z40`: entries with `decal` render Track 2 full-face anime decals with `0.0px` silhouette shift; parametric entries drive Track 1 11-layer live sclera-clipped eyes/lids/brows/mouth/optional `overlay`).
    - Open `poses` (`layers[]`) & `gestures` (`pose`, `replaces[]` slot replacement, additive `layers[]`) dictionaries with `fallback` chains and **generic part/joint anchored 2D tracks around `pivot`** (inline or resolved via reusable `motions` refs like `"breathe"` / `{ use, phase }`):
      - `oscillate` (`rotDeg`, `tx`, `ty`, `sx`, `sy`, `hz`, `phase`, `ease` — subsuming arm waves, breathing, and out-of-phase perched leg sway; accepts legacy shorthand aliases).
      - `keyframes` (`[{ t, rotDeg?, tx?, ty?, sx?, sy? }]`, `loop?`) and `frames` (`fps` + frame list). **Keyframe timing contract (consistent with `oscillate.hz` and `companion_pack_rig.go:102-121`):** `t` is elapsed track time in **seconds** (`>= 0`, nondecreasing); total track duration is `keys[last].t`. A single keyframe or `duration === 0` holds the last keyframe statically. `loop` defaults to `true` (wrapping `elapsed % duration` when `duration > 0`); `loop: false` clamps to the last keyframe for `elapsed >= duration`. Adjacent **duplicate timestamps** (`keys[i].t === keys[i+1].t`) define an instantaneous **step jump** at time `t` (no divide-by-zero: interpolate up to the first key at `t` for `elapsed < t`, and evaluate from the last key sharing `t` once `elapsed >= t`). Channels interpolate linearly between adjacent distinct-`t` keys, with omitted channels defaulting to identity (`0` for `rotDeg`/`tx`/`ty`, `1` for `sx`/`sy`).
    - Open `props` & `fx` registries backed by engine-shared defaults (`drone`, `mail`, `grab`, `prop-typing-desk`, comic badges/particles/floats) plus reusable prop behaviors (`attach`, `orbit`, `arc-to-landmark`, `bonk-from-edge`, `burst`) and whole-body stage physics (`stay`, `hop-bounce`/`double-hop`, `pendulum-drag`, `squash-pop`).
    - Full graceful degradation when any optional pose, gesture, expression, hair layer, or prop is omitted by a minimal BYO pack (the formatted example spans 9 lines: `ai-docs/manuals/companion-pet-rigging.md#L105-L113`).
- **Lightweight Iframe-to-Shell Active-View Relay & Deterministic Event Producers:**
  - Because the shell rail and active session iframe maintain separate WebSocket streams (`shell.js`, `dashboard-stream.js`), extend `WsShell`'s existing same-origin UI-control `postMessage` registry (`shell.js` `KINDS` / `WsShell.message`) with two `wsShell` kinds:
    - **Shell → Frame gating (`wsShell: "companion-gate"`):** `{ wsShell: "companion-gate", active: boolean }`, sent `true` only to the single currently visible frame while `window.wsCompanionConfig.mode !== "off"` and `false` to outgoing/cached frames or when mode turns `off`. Cached/background frames and all frames in `off` mode detach observers/timers and emit nothing.
    - **Frame → Shell observation (`wsShell: "companion-context"`):** throttled read-only payload carrying `sessionId`, `routeKind` (`session | tracker | settings | home`), `harness`, `model` (empty on sessionless routes), `activity` (`idle | thinking | streaming | permission | typing_user | error`), `openAskCount`, `runningSubagents`, `events` (array of edge-triggered events emitted since the last message, each `{ kind, token }`), and `landmarks` (`composer-top`, `whiteboard-ask`, `hud-roster` rectangles translated by the shell using the active iframe's `getBoundingClientRect()`).
  - **Both framed bundles integrated + clean active-frame reset:** Wire the `companion-gate` receiver and `companion-context` emitter in BOTH `dashboard-lifecycle.js` (session/index/worktree frames) AND `dashboard-settings.js` (`dashboard.tmpl:600-607`, emitting `routeKind: "settings"` with empty `sessionId`/`harness`/`model`/`landmarks`). Whenever the shell changes its active frame (`shShow` / `shStart`), immediately reset the previous frame's context, landmarks, and `auto` `(harness, model)` hint before sending `companion-gate` to the newly shown frame so prior session context never lingers.
  - **Existing navigation contract preserved (`dashboard-lifecycle.js:524-532`, `:599-604`):** Do **not** alter `WsShell.framed` or Werkschaft's top-level navigation rules. Ambient `rail-home` idle mode applies while the outer shell stays mounted on sessionless framed routes (`/`, `/w/*`, `/settings`, or while a frame is loading); non-framable URLs continue to navigate the top-level document and unload the shell cleanly.
  - **Origin/source verification:** The shell verifies `event.origin === window.location.origin`, `WsShell.message(event.data)`, and `event.source === activeFrame.contentWindow`, discarding messages from cached/inactive frames.
  - **Deterministic Event Producers & Silent Baseline Discipline (no replay on switch/reconnect):**
    - On frame activation (`companion-gate` `active: true`), session switch, or stream reconnect, each region source (board asks, HUD/tree agents, conversation entries) starts in a silent **baselining** phase and snapshots its baseline sets **after its first reconciled state arrives** (or once an unchanged-hash reconnect settles without a region delta — matching `railBaseline` in `dashboard-stream.js:507-508` and `tlBaseKeys` in `dashboard-stream.js:102-123`). Catch-up items arriving during a disconnect gap update steady-state fields (`activity`, `openAskCount`, `runningSubagents`, `landmarks`) and seed the baseline, but **never** emit one-shot reaction events.
    - **Steady-state `activity`:** read from `#r-convlive .clive[data-phase]` (`dashboard-composer-status.js:13`): `thinking` → `thinking` (`session.thinking`); `replying` or `tool` (or `runningSubagents > 0`) → `streaming` (`session.streaming` → `working_tatata`); `permission` → `permission`; active input in `#composer textarea` (debounced 2.5 s) → `typing_user` (`user.typing` → `perched_watch`); otherwise `idle` (`session.idle`).
    - **`ask.open`:** emitted post-baseline when a new open whiteboard ask ID (`TL_ASK` selector `.card.policy[id^="item-"], .arow[id^="item-"], .ckrow[data-id]:not([data-assumed])`) or a new permission wait (`#r-convlive .permwait`, `#r-tree .phase.permission`, `#r-tree .brow.perm` outside `.ag-source`) appears that was not in the baseline/seen set (`token: "ask.open:<sessionId>:<id>"`).
    - **`subagent.spawn` / `subagent.done`:** diff `#r-tree .ag-source .ag-hud-data` JSON (`dashboard-hud.js:24-33`, `pageview_hud.go:65-81,149-154`) and `#r-tree` ended-agent nodes post-baseline. A new child node ID (keyed by stable `replyId || id`) emits `subagent.spawn:<sessionId>:<nodeId>`. Because a finished non-live leaf can drop out of `HUD.Roots` and roll into `HUD.Completed`, emit `subagent.done:<sessionId>:<nodeId>` once per tracked active child when it transitions to ended/idle/closed **or** disappears from `HUD.Roots` as `HUD.Completed` increments (or when a non-fail `.mailline.recv.agent-note` / `.child-report` arrives for an untracked child), deduplicating HUD and conversation completion signals by the same child identity so a worker's return fires **at most once**.
    - **`mail.recv`:** emitted post-baseline for each new incoming mail entry key in `#convo` (`.mailline.recv:not(.child-report):not(.agent-note)[data-entry]`, `.mail-block[data-entry] .mailline.recv`, `.mail-notification[data-entry]`, `dashboard.tmpl:366,380,389`) with `token: "mail.recv:<sessionId>:<entryKey>"`.
    - **`session.error`:** emitted post-baseline when a new `.sysline.notice.fail[data-entry]`, `.sysline.compaction.fail[data-entry]`, `.mailline.recv.agent-note.fail[data-entry]`, or `.toolsline[data-entry]` containing `.brow.fail` arrives, or a tracked HUD lead/root transitions into `state === "failed"` (`token: "session.error:<sessionId>:<key>"`).
    - **`session.celebrate`:** emitted post-baseline from **one single authoritative source** — archived `#convo .toolsline[data-entry]` entries (never double-firing from transient live `.brow.done` rows in `#r-convlive`/`#r-tree`) — **only** when the entry has zero `.brow.fail` and matches a concrete commit, merge, or passing-test tool signature (`span.tool[title]` matching `git_commit` / `git_merge` / `ws/git.commit` / `ws/git.merge`, or a shell tool whose `.ba[title]` or multi-call `.bp[title]` (`page_format.go:320-340`) runs `go test`, `npm test`, `pytest`, `cargo test`, `vitest`, or `jest`), with `token: "session.celebrate:<sessionId>:<entryKey>"`. Ordinary `working -> idle` transitions and baseline/reconnect history **never** emit `session.celebrate`.
    - **Shell-local triggers:** `user.poke` (character hitbox click), `user.drag` (pointer drag start), and `idle.long` (shell inactivity timer while `activity === "idle"`).
- **Declarative 0-Token Scenario Runner (Fast Path):**
  - Implement a generic priority/cooldown scenario matcher driven by the relayed event stream + local pointer/idle triggers (`user.poke`, `user.drag`, `idle.long`), seeded with the **12 built-in starter scenarios** (`idle_roam` through `mailbox_bonk`) as a declarative data table merged with pack-provided `pack.json` `scenarios` (supporting single-beat shorthand, multi-beat `steps[]`, safe declarative `when` guards `streak`/`windowMs`/`idleMs`/`hourRange`/`routeKind`/`pose`, and `disabled: true`).
  - Pair with the always-on passive gaze priority stack.
- **Compatibility Tier Verdict — T0 (transparent):** Pure frontend shell/iframe addition gated off by default; introduces no wire protocol break, MCP tool change, or persisted store schema change.
