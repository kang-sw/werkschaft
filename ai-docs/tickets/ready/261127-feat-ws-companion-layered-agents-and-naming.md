# Companion Single-Embodiment Dual-Brain Agent Architecture: Capability Markers, Tier-1 Burst Session, Tier-2 Hidden Work Brain, and Shared Dashboard Control Binding

## Background

As Werkschaft's companion evolves toward humanoid VRM Co-Lead characters (`261126-feat-ws-companion-vrm-engine`, `344452e4`), the Step 4 Phase 1 surface (naming cleanup, phone store, `ws/companion.*` tools, messenger popup, VRM choreography) has **already landed on `develop` as `b326952ee`**. What remains is the agent architecture on top of it:

1. **Naming cleanup, phone store, `ws/companion.*` tools, posture lock, glass knock, smartphone choreography, `#companion-chat-btn` and messenger popup: landed (`b326952ee`).** This ticket does not re-implement them. It records their current shape (see `## Current Codebase Surface`) and fixes the one live defect they shipped with: the `[phone buzz: N unread]` piggyback and the posture lock are keyed on any session, because no `companion-body` / `companion-work` marker exists yet.
2. **Single-embodiment dual-brain companion (`(1744)=a`):**
   - With `261127-feat-ws-ephemeral-lightweight-harness-pool` now `.done`, `agents-plugin-tool/internal/wsdashboard/companion_director.go#L591-L601` runs passive session reactions through `CompanionEphemeralRunner` (`companion_director.go#L73-L81`) -> `companionPoolAdapter` (`agents-plugin-tool/cmd/ws-mcp/dashboard.go#L425-L453`) -> `wsagent.EphemeralPool` (`BoundedRotation`) and broadcasts `companion-command` on `regionRail` (`agents-plugin-tool/internal/wsdashboard/sse.go#L636-L647`).
   - `CompanionEphemeralRequest` (`companion_director.go#L57-L69`) and `companionPoolAdapter.Execute` (`cmd/ws-mcp/dashboard.go#L433-L453`) do not plumb `ResponseSchema` (supported on `wsagent.EphemeralRequest` at `agents-plugin-tool/internal/wsagent/ephemeral_pool.go#L68`); `(1744)=a` retires the zero-MCP triage fork that would have needed it, so that seam stays unplumbed. There is still no **Tier-1 Companion burst session** -> **Tier-2 Hidden Work Brain** `delegate_work` loop and no session-marker-scoped enforcement.
3. **Dashboard control is spun out.** The shared dashboard control MCP layer (`ws/daemon.{curl,tabs,dom,ui,screenshot}`, the existing `dashboard-stream.js` WebSocket bridge, `wsagent.Record` per-session opt-in for regular leads, and a top-level `shell` non-blocking 1-Click approval banner) is owned by `261128-feat-ws-dashboard-control-mcp-api` (owner-settled on the whiteboard topic `dashboard-control-mcp-api`). This ticket only binds the Tier-2 brain to it in Phase 2.

- **Single-Embodiment · Dual-Brain ("Companion AI's AI") — settled `(1744)=a` (owner; refines `(150)=a` and `(1737)=a`, with `(151)=a` wake-on-event and `(152)=a` delegated coding):**

    - **Tier-1 Companion (sole embodied persona):** exclusively owns the VRM body, `ws/companion.*` (`phone_pickup`, `phone_read`, `phone_send`, `phone_putdown`, `delegate_work`), the server-enforced `laptop | phone` posture lock, the Embodiment Lease, and all direct messenger conversation with the user.     - **Tier-2 Hidden Work Brain (dedicated daemon-launched hosted session, `(1737)=a`):** has zero body control, zero `ws/companion.*` tools, zero persona prompt, and never speaks to the user. Tier-1 invokes it via `companion.delegate_work(brief)` with a lossless curated task brief (no artificial length cap: all needed context, constraints, and references travel uncompressed).   - **Rejected:** A Tier-2 persona or body that talks to the user (split personality and chat-context handoff on first activation); an Embodiment Lease handoff between tiers; a lossy or line-capped `delegate_work` brief; keeping the separate zero-MCP `ResponseSchema` triage fork.

Read-only inspection and non-destructive UI navigation proceed without extra prompts.

- **Embodiment Lease semantics — `(1739)`, simplified by `(1744)=a` (technical):**
  - **Chosen:** One in-memory lease per daemon (the companion is app-scoped) in `companion_phone.go`, a record `{holder, posture, deadline}` (the landed `b326952ee` store has `leaseOwner`, `ReleaseOnTurnEnd`, and a held-by-other check that only applies in `phone` posture; Phase 1 extends it to the semantics below, renaming `leaseOwner` to `holder` is optional). `holder` is only the Tier-1 Companion session key: no tier-to-tier transfer exists. The lease is held in `phone_active` and in `laptop_work`, and free in `laptop_ambient`/`laptop_sleepy`; ambient director ticks skip while it is held. `laptop_work` means Tier-1 is in laptop posture or at least one delegation is in flight (`(1748)`). Acquire is an atomic compare-and-set under a mutex: it succeeds when the lease is free or already held by the same session key, and a `phone_pickup` from a different Tier-1 key returns `lease_held` only while the current holder's session is live. A holder close or crash clears the holder (the `laptop_work` visual and delegation state continue while a delegation is in flight), so a relaunched Tier-1 with a new key can acquire and is never locked out until a deadline. `phone_pickup` flips `posture -> "phone"` (also after a wake acquire, and while a delegation is in flight, without touching Tier-2). `phone_putdown(work)` flips `posture -> "laptop"`; `phone_putdown(normal|facedown_merong)` and the turn-end failsafe release the lease unless a delegation is in flight, in which case posture settles to `laptop` (`laptop_work`) and the lease stays held. A wake delivery to Tier-1 (user message or delegation completion) itself acquires the lease with `posture = "laptop"`, so `delegate_work` is callable directly after a wake while `phone_read`/`phone_send` need a `phone_pickup` first. The wake shows the `buzz` visual and the `laptop_work` typing visuals start only once a delegation is in flight or Tier-1 makes a laptop-posture tool call (`phone_putdown(work)`, `delegate_work`), so a trivial message never plays laptop typing before pickup. A buzz never preempts: it lands in the unread inbox and the `[phone buzz: N unread]` piggyback. The lease carries a sliding idle deadline (a named constant, default 5 minutes, renewed by each Tier-1 tool call and turn-activity signal) while no delegation is in flight; with a delegation in flight the deadline is renewed by Tier-2 turn-activity signals and uses a longer named constant (default 30 minutes), so a hung or vanished turn cannot strand it. Forced release also fires on Tier-1 close or crash (see `(1743)`). Every release with a non-empty unread inbox re-wakes Tier-1 (`(1749)`), so a message that arrived during `phone_active`/`laptop_work` is never left unanswered.
  - **Rejected:** Per-session or persisted (disk-backed) leases (violates the `performance.md` hot-path rule and adds no value for one app-scoped companion); no deadline (a hung turn strands the lease); any lease handoff between Tier-1 and Tier-2.
- **Posture-lock "work tools" definition — `(1740)` (technical):**
  - **Chosen:** The landed `b326952ee` predicate `companionPostureRefusal` keys on the caller's session key and applies to every session that reaches the companion host; Phase 1 re-keys it, and the `[phone buzz: N unread]` piggyback, onto the `companion-body` marker so ordinary leads never see the lock or the badge. A fixed per-marker base allowlist for `companion-body`, enforced server-side at every posture in `sessionToolAccess` and in tool discovery (`ws/companion.*`, `mailbox.*`, read-only discovery; a launch-time profile alone is never the enforcement), so Tier-1 holds no lead-level mutating tool at any posture. The posture rules below apply within that base. Allowlist under `phone` posture, evaluated server-side for the Tier-1 `companion-body` session only, next to `isLeadOnlyTool`/`roleAllowsTool` in `server_inventory.go`: permit `ws/companion.phone_{pickup,read,send,putdown}`, `mailbox.*`, and read-only discovery (`callDiscoveryTools`, `workflow_manual`, `workflow_state`); every other tool, including `ws/companion.delegate_work`, is a work tool and is blocked. Under `laptop` posture only `phone_read`/`phone_send` are blocked from that base. A blocked call returns a structured `posture_locked` error naming the required `phone_putdown`/`phone_pickup`. The Tier-2 session is never subject to the posture lock and simply has no `ws/companion.*` tools.
  - **Rejected:** An enumerated deny list of work tools (fail-open for every future tool).
- **Tier-1 wake, launch, and failure behavior — `(1749)` (technical; replaces the retired `(1741)` triage-schema contract):**
  - **Chosen:** A user messenger message is stored in the in-memory inbox, emits the `buzz` SSE state, and wakes the Tier-1 session through `Runner.Deliver` (launching it lazily on first use through the existing hosted-session launch path with the configured lightweight profile/tier and a minimal `companion-body` tool inventory, persona built from the pack's `CompanionPersona`). Idle Tier-1 is a sleeping hosted session (zero tokens). If the director is disabled or unconfigured, or the Tier-1 launch/turn errors, the message stays unread, the phone is put down `normal`, and the cosmetic fallback applies; a release-time re-wake retries at most a named bound (default 3 consecutive failures) and then the messenger shows an `unavailable` state until the next user message resets the count. No message is dropped.
  - **Rejected:** A zero-MCP `ResponseSchema` triage fork in front of Tier-1 (retired by `(1744)=a`); unbounded re-wake retries (a persistent launch failure would loop).
- **`delegate_work` contract — `(1748)` (technical, within `(1744)=a`):**
