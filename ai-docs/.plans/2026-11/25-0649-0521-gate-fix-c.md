### Important

- agents-plugin-tool/internal/wsdashboard/assets/dashboard-bg-exec-monitor.js:317 - A job change elsewhere can cancel a valid Stop hold and remove keyboard focus. The daemon broadcasts its job revision to every stream (daemon_runtime.go:78), so a separate tree starting or finishing a job causes the open popup to fetch its list and redraw it even when every local job is unchanged. The redraw removes all list rows at line 391 and destroys the active hold at line 474. Start a second tree's job midway through a 1.5-second hold and the original target never receives Stop. Patch by job ID, retain the selected dock's controls while the target and permission stay stable, and add a browser regression that changes a peer job during the hold and checks node identity and focus.
- agents-plugin-tool/internal/wsdashboard/assets/dashboard-bg-exec-monitor.js:635 - Each new live-output poll synchronously stats the dashboard's authentication secret. A valid localhost cookie runs through access.go:134 and localhost_auth.go:61–62 on each request, then access.go:113 calls ReadFileCached, which stats even on a cache hit (internal/wsstate/read_cache.go:40). Watch a job producing a chunk on each read and the 500 ms interval causes about two stats per second per open viewer, before any job work. Preserve cookie revocation semantics while removing that filesystem touch from the polling path, or use authenticated event delivery for the tail. Measure warm-path file operations through the real handler as required by performance.md.
- agents-plugin-tool/internal/wsdashboard/assets/dashboard-bg-exec-monitor.js:714 - The tail's 800-line cap leaves an unbounded number of bytes and text nodes inside one line. For a command that continuously writes progress separated by carriage returns, line 711 removes the separators, line 721 appends each chunk to the same span, and line 731 only limits direct children of the output element. A long-running job can keep increasing browser memory and text layout cost despite bounded server retention. Enforce a retained byte budget even inside an unfinished line, and cover sustained newline-free output in a browser test.
- agents-plugin-tool/internal/wsdashboard/exec_hud.go:161 - The read-only popup advertised by the change has no production route. A LAN-authenticated browser can receive a background count in the session page and click its unconditional button (assets/dashboard-composer-status.js:87–92 and assets/dashboard-bg-exec-monitor.js:761–764), but the list request returns 404. All successful list responses get `can_control: true` because line 201 passes the already-required `local` value. The browser test supplies false by rewriting the response (testdata/bg-exec-monitor.browser.cjs:196–201), and the Go test checks an unauthenticated peer (exec_hud_test.go:608–613). Align the trigger with the actual read authorization and verify it in a real authenticated LAN session. Preserve the localhost and Origin requirements on Stop and resolve the read-only contract explicitly before exposing commands or output to another viewer.
- agents-plugin-tool/internal/wsdashboard/assets/dashboard-bg-exec-monitor.js:275 - Hiding a browser tab pauses the tail but continues job-list requests and DOM work. The main stream deliberately stays connected for browser-hidden tabs (assets/dashboard-stream.js:465–472), its exec event still calls `bgExecWake` at line 652, and neither the wake nor the list fetch checks page visibility. Open the popup, switch browser tabs, and start or end jobs in another session. Each revision can fetch and rebuild the hidden popup. Coalesce the latest revision while hidden, abort an in-flight list request, and refresh once on show. Add a hidden-tab regression that emits an exec revision and counts list requests. The current test at testdata/bg-exec-monitor.browser.cjs:216–231 covers cached-frame tail polling and the ticker only.
