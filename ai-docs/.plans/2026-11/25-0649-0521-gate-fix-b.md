## Review findings: ws 0.52.1 release gate, segment B (7e46af3ae..50d151dba)

### Critical

- `agents-plugin-tool/internal/wsagent/compaction.go:743` - A daemon restart can lose the native-session binding or the carry-forward checkpoint during rotation. The old holder is retired and the empty native ID is persisted before the replacement starts. The replacement ID is only persisted when the runner handles its session event (`runner_events.go:49`). Once the replacement starts, the checkpoint and resume intent live only in `compactNote` and `compactResume`. For example, complete `ws/compact(lead_summary, resume=false)`, restart the daemon before the next prompt, and then send input. Recovery installs a generic restart marker (`runner_conversation.go:141`), so the replacement never receives the checkpoint. A crash earlier, after the ID is cleared and before a replacement holder exists, also removes the record's route back to the old native session. Keep a recoverable handoff through delivery of the first prompt and verify both restart windows.

### Important

- `agents-plugin-tool/internal/wsagent/runner_events.go:490` - The normal MCP recovery restart can silently discard an accepted compaction. For example, if an MCP server fails to reconnect while Stage 1 is running, its terminal event queues the native fallback (or leaves the accepted summary queued), then calls `restartIfDue` before `kick`. That restart calls `stopProcess`, which clears the pending request at `runner_events.go:980`. Order the idle transitions so the accepted compaction is settled or carried through the restart.

- `agents-plugin-tool/internal/wsagent/runner_events.go:447` - Stage 1 can request a second compaction after the harness already compacted. When Claude natively compacts during the Stage 1 prompt and emits a successful `CompactEnd`, the normal reducer counts it and queues a restore, while `compactStage1Active` stays set. On the Stage 1 terminal event, the fallback then enqueues native `/compact` because there is no pending summary. Treat the observed successful cut as satisfying that attempt and test the event ordering.

- `agents-plugin-tool/internal/wsagent/compaction.go:735` - Rotation bypasses process-end cleanup and can disable MCP recovery on the replacement. If an old holder has an asynchronous MCP check in flight, `mcpChecking` stays true. Its callback is discarded on the process-identity check (`runner_recovery.go:145`), and a failed MCP server on the replacement only queues another check behind that stale flag (`runner_recovery.go:99`). The regular process-end path resets these fields at `runner_events.go:910`. Reset process-owned MCP state across the rotation and cover an in-flight callback.

- `agents-plugin-tool/internal/wsagent/compaction.go:727` - A failed rotation leaves a successful audit cut. If the audit append succeeds and `startLead` then fails, rollback restores the old native session ID and emits `CompactFailed`, but the audit still has a non-estimated `KindCompaction`. Existing readers treat the latest event of that kind as the active context boundary (`agents-plugin-tool/internal/wsaudit/cut.go:29`), even though the resumed old session still has the prior context. Ensure the pre-retirement checkpoint cannot be read as a completed cut after rollback, and extend the failed-launch test to inspect the audit.

- `agents-plugin-tool/internal/wsagent/runner_conv.go:2028` - The dashboard intercept discards the `compactIdle` result. When a drain contains `/compact` followed by a user prompt and both the Stage 1 send and native command fail synchronously, `compactIdle` returns false. The new branch exits with the prompt persisted in `Queued`, the inbox signal consumed, and no kick scheduled. Let the failed attempt re-enter ordinary input handling or schedule a retry so the following prompt can run without another user action.

- `agents-plugin-tool/internal/mcp/compaction.go:130` - `tools/list` now takes the dashboard's authoritative state-read path just to classify the caller. Even a default-native hosted lead incurs an inbox directory read under its lock and permission-file revalidation (`agents-plugin-tool/internal/wsagent/runner_operations.go:28`). Discovery then resolves the setting from config files if no session override exists. Use the in-memory hosted-lead binding and generation-cached mode for discovery so this path respects the file-touch budget.

- `agents-plugin-tool/internal/mcp/dashboard_settings_config.go:63` - Dashboard mutation validation enforces the werk lock, while dashboard reads still use the generic `native` default and both choices (`agents-plugin-tool/internal/wsconfigservice/snapshot.go:136`, `:166`). On a fresh werk scope, or after setting the wildcard to `native`, Settings reports `native` even though the runner and MCP config reader resolve `ws`. Project the effective value and allowed choices from the descriptor on the dashboard read path as well.

- `agents-plugin-tool/internal/wsagent/ws_managed_compaction_test.go:207` - The three backend cases share a fake that only records `StartSpec`, and the test ends before the replacement reports its native ID. It therefore passes even if no fresh native ID is persisted or a runner restart resumes the wrong session. The audit assertion also stops at the old fake process's checkpoint, so it never checks real persisted source continuity. Add the ticket's real protocol, restart, and audit-store fixtures, plus the bidirectional override and record compatibility checks. The existing fallback cases also leave the combined mid-session toggle and successful Stage 1 path unverified.
