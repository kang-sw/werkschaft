### Critical

- agents-plugin-tool/internal/wscred/local_endpoints.go:76 - A different config home can permanently erase valid endpoint keys. Save a key under config home A, stop the daemon, keep the same cache, and use `credential endpoint set` under config home B. The offline CLI resolves the credential file from the cache and passes B's config to the same store (`agents-plugin-tool/cmd/ws-mcp/credential_cli.go:224,343,366`). Reconciliation treats every key absent from B's map as retired, even before the requested edit. Starting the new daemon under B also triggers this sweep (`agents-plugin-tool/cmd/ws-mcp/dashboard.go:519`, `agents-plugin-tool/internal/wsagent/runner_startup.go:90`). The 0.52.0 loader only replaced the in-memory catalog (`585bb9d6c:agents-plugin-tool/internal/wscred/local_endpoints.go:14`), so switching back to A recovered the key. The new writer scrubs it permanently. Limit retirement to keys the edited config can establish it retired, and extend the existing alternate-home CLI test at `agents-plugin-tool/cmd/ws-mcp/credential_cli_test.go:280` to cover a write and reopening A.
- agents-plugin-tool/internal/wscred/local_endpoints.go:64 - A preserved direct config write can reactivate a retired key after failed cleanup. Change endpoint A to B while credential publication is blocked, for example by a Windows reader that denies write sharing (`agents-plugin-tool/internal/wscred/private_file.go:112`). Reconciliation publishes B and leaves A's key intact after the error. Restore A through lead-authorized `config.tune` after the reader closes. That path commits the config before requesting a reload (`agents-plugin-tool/internal/mcp/server_dispatch.go:497`, `agents-plugin-tool/internal/mcp/dashboard_config.go:17`). The reload now considers A's hash valid and serves the old key again. Enforce the retirement guard for the legacy writer while preserving its call contract. The failure test at `agents-plugin-tool/internal/wscred/local_endpoints_test.go:102` restores only through the guarded endpoint API. Add the legacy restore case to it.
- agents-plugin-tool/internal/wscred/openai_store.go:243 - The owner cannot revoke an existing background-use grant once the account needs reauthorization. An unusable refresh clears the ID token and scopes while preserving consent (line 363). Settings still enables the switch for a previously allowed account (`agents-plugin-tool/internal/wsdashboard/assets/dashboard-settings-account.js:459`), but the route rejects the revocation. A later successful sign-in carries the still-true consent forward (line 183), allowing background use despite the owner's attempt to withdraw it. Allow revocation for the active registration regardless of current grant readiness. The browser test exercises the toggle after credential loss, but its mock accepts every consent write (`agents-plugin-tool/internal/wsdashboard/testdata/account-settings.browser.cjs:105,277`). Cover this case through the real store.

### Important

- agents-plugin-tool/internal/wscred/openai_consent.go:53 - Prompt IDs repeat across daemon restarts. Dismiss the first prompt, restart the same build, and leave the dashboard tab open. The first refusal from the successor reuses ID 1, which the tab still hides (`agents-plugin-tool/internal/wsdashboard/assets/dashboard-stream.js:25`). A stale action carrying that ID also matches a new pending prompt because the store validates only the counter for banner actions (`agents-plugin-tool/internal/wscred/openai_store.go:233`). Scope prompt identity to the daemon instance and test reconnect and stale POST handling.
- agents-plugin-tool/internal/wscred/local_endpoints.go:184 - An endpoint edit blocks credential reads while it waits on the global config file lock. With a concurrent config writer holding that lock, an Account edit can make unrelated turns and Account status wait for up to ten seconds before config I/O begins (`agents-plugin-tool/internal/wsconfig/config.go:872`, `agents-plugin-tool/internal/wsconfig/resolver.go:12`). Both credential and status reads acquire the same store mutex (`agents-plugin-tool/internal/wscred/store.go:403,418`). Keep the config-lock wait off the read path and exercise a held config lock with a concurrent credential read, as required by the interactive I/O rule (`ai-docs/manuals/performance.md:34`).
