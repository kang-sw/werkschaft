## Review findings: ws 0.52.1 release gate, segment E (f4b2ae29f..0f27fd010)

### Critical

- agents-plugin-tool/internal/wsagent/agent_delivery.go:221 - Heartbeat expiry can still close an ancestor while a younger leaf survives across a newly closed bridge. Let the heartbeat find a quiet tree A → B → C, with A due and C too young to expire independently. After the walk releases the registry lock, release B's checkout while C is bound elsewhere. The release moves B to the retained closed records without closing C (`worktree_release.go:305–325`, `dead_binding.go:120–127`). Expiry then calls `CloseConversation`, which takes a fresh open-only descendant snapshot (`runner_operations.go:512–531`, `children.go:843–854`). That snapshot misses C and closes A. The purge guard retains A's history, but A is already closed. Make expiry validate the bridge rule against the tree it actually closes and add a regression that pauses expiry before closing B through the release path.
- agents-plugin-tool/internal/wsagent/dead_binding.go:198 - Restored occupancy can miss the checkout it was persisted to protect. A worker can start with its project root elsewhere and a CWD symlink into the pooled checkout. Spawn stores the supplied CWD (`spawn.go:122–125,181–194`), and release captures the canonical checkout in the closure. If the link is removed or redirected before the successor starts, recomputing `canonicalBinding` no longer puts either path inside that checkout. `boundDeadProcesses` filters on those two paths before comparing the persisted checkout at lines 246–250, so the pool can reacquire it while the holder still runs there (`mcp/worktree_tools.go:1178–1188`). Use the persisted checkout as a positive occupancy match and cover a changed CWD symlink in the replacement test.

### Important

- agents-plugin-tool/internal/wsagent/dead_binding.go:201 - Restored occupancy can reappear after the holder exits. While the listing explicitly reports the child exited, the query skips it but retains the binding for its closed record (lines 226–244). Once the manager removes the exited holder (`wsholder/manager_scan.go:182–208`), an unrelated unreadable holder descriptor can keep the global census incomplete (lines 101–116 of that file). The next query now treats this absent holder as potentially live. Startup finalization also skips an incomplete census (`runner_startup.go:489–490`). Preserve affirmative exit evidence for the specific holder across incomplete listings and test acquisition after exit. The replacement regression at `safe_stop_test.go:539–554` currently stops at the live assertion.
- agents-plugin-tool/internal/wsstate/read_cache.go:53 - The generic cache refill now sleeps synchronously on interactive Windows requests. Dashboard LAN authentication calls the cache on a guarded request (`wsdashboard/access.go:84–90,113,148)), and localhost cookie validation does the same (`wsdashboard/localhost_auth.go:61–79`). A denied read on a cold or changed file now retries for about two seconds because the common helper also retries permanent `ERROR_ACCESS_DENIED` (`wsstate/replace_file_windows.go:121–145`). The eventual error is returned, but the request waits through repeated file opens. This violates the interactive I/O rule in `ai-docs/manuals/performance.md:34–43`. Scope recovery to the publication race without extending synchronous waits on the interactive cache path, or obtain approval for a measured exception.
